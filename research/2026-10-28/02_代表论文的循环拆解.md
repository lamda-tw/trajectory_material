# D7 / D8 代表论文：每一轮究竟做了什么

调研日期：2026-10-28。配套阅读：[共同机制与业务讨论](01_D7与D8_循环流程与共同机制.md)；[综述与原文索引](03_综述入口与文献核查索引.md)。

本文件按机制选取 16 篇 2024 年及以后首次公开的论文，不以“最新排行榜”排序。较新的研究用于展示流程变化，不视为已经成熟的生产方案。每篇的五步映射区分论文方法与工程扩展；不能因为映射到了附件，就认为原作者实现了全部自动化环节。

## P01. SPIN：用上一轮的自己，暴露与示范数据的差距

**论文：** [Self-Play Fine-Tuning Converts Weak Language Models to Strong Language Models，2024](https://arxiv.org/html/2401.01335v3)。重点读 §4 与 Algorithm 1。

### 核心想法与一轮流程

已有一批高质量的「问题—示范答案」。普通微调只是反复模仿示范；SPIN 让当前模型也回答同一批问题，把模型当前会写出的答案作为对照，再学习靠近示范数据的分布。

```text
固定问题与示范答案
    → 当前模型生成同题答案
    → 示范答案与模型答案形成对比
    → 用对比目标训练新模型
    → 新模型替代旧模型，生成下一轮对照答案
```

递归体现在：下一轮的“对手”随模型更新而变化。早期的对照容易，后期对照可能更接近示范。这里没有一个必须单独训练的外部裁判；论文的博弈推导最终落实为语言模型的训练目标。

### 三个技术问题

- **信号怎么设计？** 根据来源，把示范答案作为目标，把当前模型生成内容作为对照；不是为每对答案额外收集人工偏好。
- **改什么、策略空间是什么？** 改语言模型参数，改变同题不同回答的生成倾向。模型结构和示范数据分布并不因此自动扩展。
- **信号怎么推动更新？** 对比式目标利用新模型相对旧模型的概率变化，学习区分示范与模型生成分布。可理解为“在当前自己容易混淆的地方继续贴近示范”，不能简单理解为多训练一遍相同 SFT 数据。

### 映射附件五步

提出：研究者预先设定示范分布与更新目标；实施：生成对照并训练；评价：论文用下游任务比较迭代效果；存储：各轮样本与模型承担经验载体；采用：新模型进入下一轮。生产级自动诊断与回滚不是其核心算法。

### 证据与适用边界

论文报告多轮自对弈微调相对起点的收益，并分析不同迭代的效果。但理论分析依赖设定，不能据此断言模型会无限提升，或超越示范数据所代表的能力边界。

**需要记住：** “示范优于当前输出”是分布层面的训练设定，不保证每条模型答案都比对应示范差。适合有可信示范、希望利用自生成对照继续改进的情况；若业务已有更直接的结果反馈，也应比较其他路线。

## P02. ETO：不仅看专家怎么成功，也看自己为什么走向失败

**论文：** [Trial and Error: Exploration-Based Trajectory Optimization for LLM Agents，ACL 2024](https://aclanthology.org/2024.acl-long.409/)。重点读 §3、Algorithm 1、迭代实验。

### 核心想法与一轮流程

Agent 看过专家示范，不代表自己行动时不会犯错。ETO 先让模型模仿成功轨迹，再让它在环境中探索，收集其自身会犯的失败，与同任务的成功轨迹对比。

```text
专家轨迹训练初始 Agent
    → 当前 Agent 实际探索环境
    → 收集失败/较差轨迹
    → 与同任务成功轨迹配对
    → 轨迹级偏好训练
    → 新 Agent 再探索，收集新的失败
```

例如，同样是“找到两个目标物并放到指定位置”，专家路径完成任务，模型路径可能只找到一个就停止。训练不只是告诉模型“最后一步错了”，而是比较这两种完整行为序列。

### 三个技术问题

- **信号：** 环境提供任务结果，成功轨迹作为较好行为、失败轨迹作为较差行为；主体方法依赖专家轨迹，论文另讨论缺少专家时的自对弈设置。
- **对象与空间：** Agent 参数，以及它在任务说明和历史观察条件下生成思考与行动的策略。
- **连接方式：** 轨迹 DPO 类目标改变成功轨迹相对失败轨迹的概率。环境观察是输入上下文，模型学习的是自己产生的思考/行动 token；不是训练模型去预测环境返回的所有文字。

### 映射附件五步

提出：由新收集的失败暴露薄弱行为；实施：构造正负轨迹并训练；评价：任务成功率、奖励及行动效率；存储：轨迹和模型版本；采用：更新后的 Agent 用于下一轮探索。论文的迭代实验不等于自动上线流程。

### 证据与适用边界

作者在 WebShop、ScienceWorld、ALFWorld 等交互任务上比较示范微调与探索后训练，支持“自己的失败具有补充价值”。这些环境并不是你们的网络或运筹业务，迁移需要重新验证。

**需要记住：** 整轨迹偏好提供方向，但不自动识别具体哪个动作导致失败。它适合能重放、能评价的 Agent 任务；环境昂贵或成功轨迹很少时，数据成本是关键。

## P03. DeepSeek-R1：固定验证标准，也能驱动模型不断改变

**论文：** [DeepSeek-R1: Incentivizing Reasoning Capability in LLMs via Reinforcement Learning，2025](https://arxiv.org/html/2501.12948v1)。本卡采用最初技术报告的 §2.2—2.4，区分 R1-Zero 与完整 R1。

### R1-Zero 的最小循环

```text
当前模型对一题生成一组解答
    → 用规则检查答案正确性与输出格式
    → 比较组内奖励，形成相对优势
    → GRPO 更新模型
    → 新模型生成下一批解答
```

模型不必先看到每道题的人工推理示范。它尝试不同推理方式，外部结果检查给出学习依据。所谓“自我反思行为出现”，指模型的输出行为在训练中发生变化，不是它自行设计了 GRPO 或修改了训练程序。

### 完整 R1 并非“纯 RL 一直重复”

```text
少量冷启动数据 SFT
    → 面向推理的 RL
    → 从 RL 检查点筛选推理数据，结合通用数据
    → 用这些数据重新微调基座模型
    → 面向多场景的进一步 RL
```

最后阶段根据任务使用不同奖励，包括推理任务的规则奖励以及通用场景的模型奖励。报告还研究将大模型生成数据蒸馏给小模型；那是教师—学生流程，不应与同一模型的循环混为一谈。

### 三个技术问题

- **信号：** R1-Zero 以准确性与格式为核心；完整 R1 的阶段和任务决定奖励类型。
- **对象与空间：** 解题模型的输出策略，主要是推理与回答文本的概率分布；并非训练一个独立步骤评价器。
- **连接方式：** GRPO 用同组回答的奖励形成相对更新权重，并约束更新幅度。奖励来自规则，也能优化语言模型，不需要规则本身可微。

### 映射与证据边界

提出：训练任务与奖励设计由研究者设定；实施：重复采样、打分、更新；评价：数学、代码等基准；存储：训练数据与检查点；采用：按既定阶段组织新版本。论文没有证明“系统自主决定所有后续训练实验”。

**需要记住：** 这是“D7 使用验证能力”，不是“D8 自动进化”。其结果支持可验证奖励的潜力，但不能说明任意基座、任意任务都能靠纯 RL 得到同样收益。长推理、采样和训练成本也必须进入业务比较。

## P04. SCoRe：专门训练“把错答案改对”，而非只训练答题

**论文：** [Training Language Models to Self-Correct via Reinforcement Learning，2024](https://arxiv.org/html/2409.12917v1)。Google DeepMind；重点读 §4—6。

### 它发现了什么问题

让模型看一批“错误答案→正确修改”的示范，或只奖励第二次答案正确，都未必产生稳定自纠错。模型可能只学会第一遍尽量答好，第二遍重复原答案；到了新题上，依旧不会处理自己实际犯的错。

### 一轮怎样发生

```text
当前模型初答 → 基于初答再回答 → 检查两次答案
    → 更新生成初答与修正答案的能力 → 新模型再生成两轮尝试
```

训练有两个阶段：第一阶段约束第一遍输出分布接近基座，重点培养第二遍修正能力；第二阶段联合优化两遍作答，对“错→对”额外奖励，对“对→错”施加相应惩罚。原文还描述交替应用这两个阶段。

### 三个技术问题

- **信号：** 两次答案各自的正确性，以及第二次相对第一次是否进步。
- **对象与空间：** 同一个模型在不同上下文下的行为；第二次输入包含第一次作答，所以训练的是条件修正策略。
- **连接方式：** 在线多轮策略梯度结合约束和奖励塑形。第一遍保持正确也有价值，不能把方法简化成“故意先答错再修正赚奖励”。

### 映射与证据边界

提出：研究者识别“不修正”的行为塌缩；实施：两阶段 RL；评价：初答、修正后效果及错误转移；存储：训练轨迹和参数；采用：新策略再次产生自己的纠错轨迹。

论文在数学与代码任务上比较 SFT、简单多轮 RL 和 SCoRe，支持专门学习自纠错策略的必要性。**训练时用外部正确性反馈，推理时不需要外部纠错提示**，这两句话并不矛盾。它是 D7 的重要变体，不是独立裁判持续改进的 D8 系统。

## P05. Absolute Zero：自己出题，但用执行环境约束题与答案

**论文：** [Absolute Zero: Reinforced Self-play Reasoning with Zero Data，2025](https://arxiv.org/html/2505.03335v1)。重点读 §3、Figure 4。

### 一轮怎样发生

同一个模型扮演出题者与求解者。它围绕「程序、输入、输出」三元组设计任务，例如给程序和输入预测输出，或者给程序和输出反推可能输入。

```text
参考历史有效任务，提出新程序/任务
    → Python 执行，过滤无效提议并构造可验证问题
    → 当前求解角色尝试解题
    → 执行验证答案，估计任务难度
    → 用不同奖励更新出题与求解角色
    → 更新后的模型继续出题与求解
```

### 三个技术问题

- **信号：** 求解者按答案可验证的正确性获得奖励；出题者根据求解成功率获得学习潜力奖励。原文的出题奖励对全对和全错任务给零，对其余情况偏向仍可偶尔解出的较难题，并非简单“成功率越低越好”。
- **对象与空间：** 同一模型的两种条件生成策略：生成有效任务、生成任务答案。程序执行器和验证逻辑不是同时被训练的对象。
- **连接方式：** 把两种角色的奖励接入多任务 RL，分别改善出题与求解。历史任务缓冲区提供下一轮条件与多样性参考。

### 映射与证据边界

提出：模型产生下一轮练习；实施：执行验证和双角色训练；评价：代码及数学推理基准；存储：有效三元组与模型；采用：新模型参与新任务构造。它比固定题集多了一层任务分布反馈。

论文的“zero data”不是零预训练知识、零规则、零环境设计。实验支持在所设代码环境中自生成课程的价值，不能直接说明自动生成任意业务场景都有效。**这是 D5 + D7；执行器固定，不能据此声称 D8 也在自学习。**

## P06. R-Zero：出题器追踪求解器，但标签来自模型共识

**论文：** [R-Zero: Self-Evolving Reasoning LLM from Zero Data，2025](https://arxiv.org/html/2508.05004v1)。重点读 §3.1—3.4。

### 一轮怎样发生

```text
冻结求解器 → 训练出题器提出让它有分歧的问题
    → 出题器生成题库
    → 求解器多次作答，多数答案作为伪标签
    → 筛选具有适当共识程度的问题
    → 冻结出题器，用伪标签奖励训练求解器
    → 新求解器成为下一轮出题器的参照
```

它与 AZR 的共性是任务和求解能力共同变化；关键差异是这里没有用代码执行器建立答案真值，而用当前求解器的多次输出形成伪标签。

### 三个技术问题

- **信号：** 出题奖励来自求解器答案的一致程度，并有重复与格式约束；求解奖励来自答案是否匹配所构造的伪标签。
- **对象与空间：** 两个从同一基座出发的模型，分别负责出题与回答；在不同阶段交替冻结和训练。
- **连接方式：** 两边均使用 GRPO。出题策略被推向产生适当分歧的题；求解策略被推向更常给出伪标签答案。

### 映射与证据边界

提出：当前出题器给出新题；实施：投票构建数据并交替训练；评价：独立推理基准；存储：题库、伪标签和检查点；采用：新求解器进入下轮。

原文有数学、通用推理及组件分析。**与多数答案一致，不等于已经验证事实正确。** 论文将伪标签一致性用作训练指标，业务讨论时必须保留“伪”这个字。若模型系统性地答错，投票未必能发现错误。它主要补充弱外部监督下的研究方向，不应直接替代可用的业务验证器。

## P07. Self-Taught Evaluators：裁判也能通过筛选自己的评价来学习

**论文：** [Self-Taught Evaluators，2024](https://arxiv.org/html/2408.02666v1)。Meta；重点读 §3.3—3.5。

### 最值得理解的标签构造

先有一条用户指令 x，模型正常回答得到 A。再把指令改成一个相关但含义不同的 x′，为 x′ 写一个好答案 B。相对于原始 x，B 预期不如 A，因为它实际上回答了另一个问题。

例如原问题要求“解释三种方法的差异”，改写后要求“只介绍第一种方法”。B 可以写得很好，但没有完成原问题。这样可以自动构造预期的 A 优于 B，而不直接依赖裁判当次的自评分数。

```text
构造答案优劣对
    → 当前裁判生成多个“分析 + A/B 判断”
    → 保留判断符合构造标签的评价输出
    → 用这些输出监督训练新裁判
    → 新裁判重新标注同类训练案例
```

### 三个技术问题

- **信号：** 答案对构造时得到的预期优劣标签，以及裁判结论是否匹配标签。
- **对象与空间：** 裁判参数，输出空间是评价分析与最终选择。
- **连接方式：** 拒绝不符合标签的评价，挑选可用判断进行 SFT。输入中的问题与两份回答是被评价材料；学习目标是裁判自己的评价输出，不是把坏回答当示范模仿。

一个容易遗漏的细节：**原文每轮微调从 seed model 重新初始化，而不是必然在上一轮参数上接着训练。** 递归仍存在，因为上一轮更好的裁判用于产生下一轮训练判断。递归的是数据与标注能力，不要求所有方法都连续累加权重更新。

### 映射与证据边界

提出：构造有区分力的指令和答案对；实施：重标注、筛选、SFT；评价：RewardBench 等外部评价任务；存储：合成对与评价文本；采用：新裁判作为下一轮标注器。

报告显示迭代方法改善了评价基准效果，但“符合构造标签”只校验最终选择，不保证解释每句话正确。构造的负例也可能偏向“答非所问”，难以覆盖所有事实性和专业业务错误。它是非常直接的 D8 循环，值得优先阅读。

## P08. GenRM：让裁判先分析，再把判断作为文本输出

**论文：** [Generative Verifiers: Reward Modeling as Next-Token Prediction，2024](https://arxiv.org/html/2408.15240v1)。Google DeepMind 等；重点读 §3、Figure 3。

### 它改变了评价器的哪一部分

常见评分模型直接输出一个数。GenRM 保留语言模型的生成能力，把任务写为：“这个解答正确吗？Yes / No。”更进一步，GenRM-CoT 先生成验证分析，再给出判断。

```text
带正确性标签的问题—解答
    → 构造 Yes/No 或“验证分析 + Yes/No”的监督目标
    → 与正确解题示范混合训练
    → 得到生成式验证器
    → 推理时评价多个候选，选择分数较高者
```

### 三个技术问题

- **信号：** 解答正确性标签；CoT 版还需验证分析。在 GSM8K 的合成分析构造中，作者使用训练时可获得的参考解帮助评价模型指出问题。
- **对象与空间：** 验证模型参数；输出空间包括判断 token 与可选的验证文本。共同训练正确解题示范，是为了让生成和验证能力产生迁移。
- **连接方式：** 监督微调提高正确验证输出的概率。推理分数可取 Yes token 的概率；多次生成验证分析时，对各次 Yes 概率取平均，而不是只看分析是否“听起来有道理”。

### 训练与推理的区别

训练构造验证分析时可以参考标准依据；推理时没有标准解可供裁判照看。增加验证采样次数是推理计算扩展，不是裁判在每道测试题上继续更新权重。

### 映射与证据边界

提出：选择生成式验证这一建模方式；实施：构造数据并训练；评价：验证与候选重排效果；存储/采用：得到可复用验证模型。**原文不是自动提出新训练方案、再无限循环的 RSI 系统。**

论文在算法任务与数学任务上比较判别式、生成式以及多次验证，支持生成式验证的价值。对业务而言，应同时比较判断收益和额外 token 成本；输出较长分析，不保证其推理受到逐句真值监督。

## P09. Qwen PRM Lessons：必须说清你训练的是“步骤正确”还是“以后可能答对”

**论文：** [The Lessons of Developing Process Reward Models in Mathematical Reasoning，2025](https://arxiv.org/html/2501.07301v2)。Qwen / Alibaba；重点读 §2—4。

### 问题从哪里来

一种常见自动标注法是：从某个推理前缀继续完成多次，若能得到正确答案，就认为这个前缀或步骤较好。但后续模型可能纠正前面的错误，也可能把正确前缀续写坏。于是，“未来成功率”并不等于“当前步骤正确率”。

这篇文章不只是提出 PRM，而是系统研究如何避免把错误标签与错误评价指标结合起来。

### 数据与训练流程

```text
有参考答案的问题 → 模型生成分步解答
    ├─ 从步骤继续采样，得到完成结果信号
    └─ LLM judge 判断错误步骤位置
        → 保留两种方式对错误位置一致的案例
        → 训练过程奖励模型
        → 同时测试答案筛选与步骤识错能力
```

### 三个技术问题

- **信号：** 步骤正确性标签，以及不同标注方式的一致性过滤；不能直接把每个前缀的续写成功率当作可靠语义真值。
- **对象与空间：** 对「题目 + 当前推理前缀」输出步骤评分的模型。原文比较硬标签分类与软标签回归等设置。
- **连接方式：** 对步骤位置上的预测做监督训练。正文训练设置中，信号落在各步骤末 token 的评分上，而不是把整个解答每个 token 都当作独立的正确/错误标签。

### 映射与证据边界

提出：发现过程监督与标签、评价之间错位；实施：构建与过滤数据、训练 PRM；评价：Best-of-N 与 ProcessBench 识错任务；存储：步骤标签和模型；采用：把验证过的 PRM 用于选答案或后续系统。论文主要是 D8 构建与方法诊断，不是自动重启的完整递归循环。

**需要记住：** 用 PRM 选出的最终答案更准，不一定说明它更会识别过程错误。若业务关心推导、计划或约束检查的可靠性，必须直接评价这些能力。两种标注方式一致也不是绝对保证，它们仍可能共享偏差。

## P10. DeepSeek-GRM / SPCT：把“怎样评价”也变成可训练的推理任务

**论文：** [Inference-Time Scaling for Generalist Reward Modeling，2025](https://arxiv.org/html/2504.02495v3)。DeepSeek 与清华相关研究者；重点读 §3—5。

### 一轮怎样发生

给模型看问题和一个或多个回答。它先提出这次应该看哪些评价原则，再写分析，最后给分。例如，代码回答应重视正确性与边界条件，解释性回答还要看是否满足问题要求。

```text
已有偏好/评分标签的回答数据
    → 生成原则、评价分析与分数
    → 初期筛选判断正确的样本进行微调
    → 在线生成新的评价输出
    → 检查排序/分数是否符合标签，给予奖励
    → RL 更新裁判，再生成新的评价
```

### 三个技术问题

- **信号：** 训练数据中的偏好或分数标签。多回答情况下，关键检查是是否把已标注的最佳回答排到最高；并非随意把所有分数都调高。
- **对象与空间：** 奖励模型参数；候选是各种评价原则、分析和评分文本。
- **连接方式：** SPCT 包含筛选微调与规则奖励的在线 GRPO。原文没有额外格式奖励，而用更强的 KL 约束等保持输出稳定；这里无需把这种具体选择当作所有 D8 RL 的统一做法。

### 额外的 meta RM 在做什么

推理时可多次生成评价，但某些评价过程仍有偏差。作者另训练一个标量 meta RM，输入问题、回答、原则和评价分析，预测这次评价是否符合已知标签。它筛掉较差评价，再聚合其余分数。

这是“选择较可靠的评价意见”，不等于 Meta-Rewarding 论文的“共享模型用评价偏好对一起训练”；两个名字相近，但流程不同。

### 映射与证据边界

提出：生成适配任务的评价原则；实施：裁判微调与 RL；评价：多个奖励模型基准和推理预算实验；存储：评价轨迹、标签与裁判版本；采用：新裁判提供后续评分。训练配方仍由研究者设计。

原文消融表明，未经筛选的自生成原则不必然有帮助；训练和选择原则很重要。它支持 D8 的训练与推理扩展，但不能直接证明用它训练任意业务生成器都会有净收益。

## P11. Self-Rewarding：同一模型既回答，也评自己的回答

**论文：** [Self-Rewarding Language Models，2024](https://arxiv.org/html/2401.10020v2)。重点读 §2。

### 一轮怎样发生

```text
当前模型对问题生成多个答案
    → 当前模型按固定评价量表给答案评分
    → 选高分与低分答案，剔除不形成差异的情况
    → 用回答偏好对训练新模型
    → 新模型再次同时担任回答者与裁判
```

初始模型先获得指令与评价相关的能力。需要特别区分：主实验中的提示生成使用预先准备的独立模型，并不是所有环节都由当前同一个模型实时生成；论文另讨论变体。

### 三个技术问题

- **信号：** 当前模型依据固定量表输出的分数与解释。
- **对象与空间：** 共享参数的模型；在回答模式生成内容，在评价模式打分。
- **连接方式：** 核心迭代用回答优劣对做 DPO。由于参数共享，评价能力可能一起改善，但并不是每轮都对“评价对不对”施加独立监督。

### 映射与证据边界

提出：研究者确定量表与任务生成方式；实施：自评形成偏好数据并训练；评价：回答与评价能力的实验；存储：合成偏好和检查点；采用：新模型进入两种角色。

论文给出迭代回答与评价表现的证据，但没有证明“解题更强必然评价更准”。同一模型可能同时偏爱并生成某种风格，形成自我强化。

**需要记住：** 它连接了 D7 和 D8，但 D8 的提升主要依赖共享参数带来的迁移。理解这一点，才能看懂下一篇为什么还要评价“评价意见”。

## P12. Meta-Rewarding：不仅给答案打分，也给评价意见排优劣

**论文：** [Meta-Rewarding Language Models: Self-Improving Alignment with LLM-as-a-Meta-Judge，2024](https://arxiv.org/html/2407.19594v1)。重点读 §2。

### 一轮怎样发生

同一个模型通过不同提示担任回答者、裁判和元裁判。一次循环产生两类训练对：

```text
回答者生成多个答案
    → 裁判为答案产生多份评价
        ├─ 聚合评分，构造好/坏答案对
        └─ 元裁判比较不同评价意见，构造好/坏评价对
            → 两类偏好数据一起训练模型
            → 新模型重新承担三种角色
```

元裁判看到问题、被评价回答与评价标准，再比较两个评价意见。例如，一份批评正确指出遗漏了约束，另一份只赞扬文风；训练希望裁判更常产生前者。

### 三个技术问题

- **信号：** 答案评分，以及元裁判对评价意见的相对偏好。作者还采用交换比较顺序、长度控制等处理偏差。
- **对象与空间：** 同一模型的回答与评价输出策略。
- **连接方式：** 用 DPO 同时学习答案偏好与评价偏好。与 Self-Rewarding 相比，评价行为有了更直接的训练目标。

原文为裁判训练选择评价分歧较大的案例，通过多次比较和排序获得较好/较差评价；不是简单选“打分最高的评价意见”。**评价意见好不好，与它给被评答案的分数高不高，是两个问题。**

### 映射与证据边界

提出：用评价分歧暴露判断薄弱点；实施：构造两类偏好对并训练；评价：回答质量与评价能力；存储：答案、评价、评价间比较；采用：新共享模型进入下一轮。

论文展示联合训练的收益，但元裁判仍可能错误。增加评价层级没有自动获得独立真值，也不应理解为已经证明可以无限递归地“裁判评价裁判”。业务可借鉴其“直接训练判断能力”的思路，同时保留执行或专家校准。

## P13. V-STaR：成功解法教生成器，成功和失败一起教验证器

**论文：** [V-STaR: Training Verifiers for Self-Taught Reasoners，2024，COLM](https://arxiv.org/abs/2402.06457)。重点读 §3、§3.1、Algorithm 1 与 §4 的预算比较。

### 一轮怎样发生

```text
当前生成器对训练问题产生多个解法
    → 参考答案或测试检查正确性
        ├─ 正确解法累积到生成器训练集
        └─ 正确与错误解法都累积到验证器训练集
    → 用累积成功数据训练新生成器
    → 新生成器继续采样，积累更丰富的正负解

累积的正负解 → 训练验证器 → 测试时给生成器候选排序
```

这里需要比“两个模型共同进化”说得更精确：**生成器的迭代数据收集很明确；原文流程最终利用各轮累积数据训练验证器，不能强行补上一条“每轮新验证器都会指导下一轮生成器训练”的箭头。** 它与 ReST-MCTS* 的紧耦合搜索循环不同。

### 三个技术问题

- **信号：** 代码测试或数学最终答案提供正确性标签。
- **对象与空间：** 生成器学习产生成功解法；验证器学习区分成功和失败解法。
- **连接方式：** 生成器用正确解法做 SFT；论文的验证器用正确解与错误解构成偏好对进行 DPO，并用训练后验证器对候选解的似然作为推理排序分数。它不是必须生成文字批评的裁判。

另一个重要细节：生成器每轮可以从预训练基座在累积数据上重新训练；递归依靠各轮产生的数据累积，而非所有轮次都在上一轮参数上连续微调。

### 映射与证据边界

提出：利用此前被丢弃的失败解法；实施：分流数据、训练两种模型；评价：单次生成与多候选验证；存储：跨轮正负数据；采用：新生成器继续采样，验证器用于最终选择。

论文有固定采样总预算下的迭代与单轮对照。它也提醒读者：**Best-of-many 与单次生成不是等成本指标。** 业务报告中需要把生成器自身进步和验证器挑选带来的进步拆开。

## P14. ReST-MCTS*：评价器不仅在最后打分，还决定下一步往哪里搜

**论文：** [ReST-MCTS*: LLM Self-Training via Process Reward Guided Tree Search，2024](https://arxiv.org/html/2406.03816v2)，NeurIPS 2024。重点读 §3、Algorithm 1。

### 一轮怎样发生

```text
当前策略提出若干下一步
    → 过程价值模型判断哪些前缀值得继续
    → 树搜索探索不同路径
    → 用最终答案依据检查完整路径
        ├─ 成功路径训练策略模型
        └─ 搜索树结果推导节点价值，训练过程模型
    → 更新后的两个模型共同参与下一轮搜索
```

想象做一道题有三种推导方向。直接采样可能一条路走到底；树搜索在多个方向间分配计算。过程模型像路口指示器，帮助搜索选择更有希望的分支。搜索结束后，又反过来提供训练这个指示器的数据。

### 三个技术问题

- **信号：** 最终答案检查，以及搜索树中从某节点能否到达正确答案、需要多少后续步骤等信息。
- **对象与空间：** 策略模型选择下一步推理；过程模型评估部分解的质量；搜索算法的基本结构由研究者设定。
- **连接方式：** 成功路径用于 SFT；从搜索树提取的节点质量值用于训练过程价值模型。评价器还通过搜索选择间接改变生成器下次能看到的数据。

这是一条非常重要的第三种连接：**信号不只直接进入损失函数，也可以先改变搜索得到什么，再间接改变训练数据。**

### 映射与证据边界

提出：搜索生成候选推理分支；实施：搜索后分别训练策略和过程模型；评价：数学/科学推理与搜索消融；存储：路径、节点标签、模型；采用：新模型组合用于下一轮。

论文报告多轮自训练与价值引导搜索的收益。但这里的“过程奖励”包含未来可达性与进展估计，不应直接等同于严格语义上的每一步正确性；最终验证还可能依赖字符串匹配或 LLM 判断。搜索覆盖和验证质量都限制了标签可靠性。

## P15. CoVera：用执行结果教模型验证，再让验证能力辅助写代码

**论文：** [Learning to Code by Learning to Verify: Execution-Grounded Co-Evolution of Code Generation and Self-Verification for Reliable Code LLMs，2026 年 10 月，EMNLP Findings](https://aclanthology.org/2026.findings-emnlp.1634/)。已核对 PDF §3.1—3.6；作者来自香港科技大学相关机构与 ETRI。

### 一轮怎样发生

```text
同一模型的生成模式：写候选代码
    → 执行已有测试，得到通过比例与成败标签
    → 同一模型的验证模式：读题与代码，输出分析和正确性判断
    → 判断是否与执行标签一致，训练验证能力
    → 经执行校准的验证分数辅助生成奖励
    → 生成能力改变，产生新一轮更有挑战的待验证代码
```

### 三个技术问题

- **信号：** 生成端主要使用执行通过比例与无效代码惩罚；验证端使用其判断是否匹配“通过全部已有测试”的标签；生成端另结合验证模型给出的辅助信号。
- **对象与空间：** 同一套参数的生成与验证角色。前者输出程序，后者输出分析与二元判断。
- **连接方式：** 两种角色分别获得 RL 信号，共同优化。验证分数接入生成奖励时进行 stop-gradient，阻断这条直接梯度通路；这不能被解读为已解决所有共享模型偏差或 reward hacking。

原文还使用回放缓冲区，混合当前及历史候选，按执行表现保留不同质量案例，避免验证器只看到某一种结果分布。

### 映射与证据边界

提出：当前生成器产生新程序案例；实施：执行校验、双角色更新；评价：生成与验证能力分别测量；存储：带执行标签的当前及历史程序；采用：更新模型参与下一轮生成与验证。

推理时可以直接生成，也可以不执行程序而用验证模式重排候选。因此，训练时“执行接地”和推理时“无执行验证”必须区分。论文实验支持其代码任务设定下的联合收益，但刚发表，外部积累仍有限。

**需要记住：** 训练标签代表通过给定测试，不代表对所有输入的形式化正确性。其最值得借鉴之处，是用外部结果持续校准自评能力，而不是用“同一模型兼任两角”代替校准。

## P16. UCoE：权重不变，也可以让评价规则参与持续改进

**论文：** [Verifier–Harness Co-Evolution for Training-Free Self-Improvement on Open-Ended Tasks，2026 年 10 月](https://arxiv.org/html/2610.17609v1)。重点读 §3 与附录的对照构造、更新准则；属于较新的探索性工作。

### 两个耦合循环

评价器以程序形式组织若干评分标准及其聚合方式。模型可以提出新标准或改变聚合，但模型权重、程序解释器等底层机制保持固定。

```text
评价器侧：提出评分程序 → 在质量对照样本上比较
           → 选择最弱类别也表现较好的程序 → 部署
           → 根据后续任务诊断提出新程序 → 留出对照验证后决定替换

任务侧：带现有记忆生成初稿 → 评价器指出一个弱点
         → 做一次局部修正 → 比较初稿与修订
         → 接受的修正可提炼为经验，影响后续任务
```

### 三个技术问题

- **信号：** 在原回答上刻意破坏一个质量属性，形成应当能区分的对照，例如遗漏必要内容或加入无关内容。选择程序时关注最薄弱对照类别，而不是只看平均分。
- **对象与空间：** 评价程序的标准与评分聚合方式，以及 Agent 的外部记忆；基础模型参数不更新。
- **连接方式：** 通过候选搜索、对照评价与版本选择修改程序。新程序需在选择集和留出对照上满足改进及回归限制，才影响后续任务。

### 映射与证据边界

这篇与附件五步更接近：模型提出候选评价程序，执行有效性检查和比较，存储任务诊断与经验，决定保留旧版或采用新版。主实验中的持久外部状态是有容量约束的程序性记忆。

但其对照样本只控制被声明的质量属性，并不提供所有开放问题的客观真值。作者用固定最终评价体系测量任务流表现；提升能否迁移取决于对照类别是否覆盖自然错误。

**需要记住：** D8 不必等于训练奖励模型。这条路线有较低的权重训练门槛，但仍需要可靠对照、调用预算与留出验证。它适合扩展讨论视野，当前不能仅凭单篇新论文视为稳健默认方案。

## 如何把这 16 篇读成少数几个问题

| 想弄明白的问题 | 对照阅读 | 最重要的差异 |
| --- | --- | --- |
| 训练一定需要精确分数吗？ | SPIN、ETO、R1 | 来源对比、轨迹优劣、数值奖励是不同信号 |
| 为什么最终答对还不够？ | SCoRe、Qwen PRM | 纠错行为和步骤识错需要对应的训练/评价目标 |
| 自动出题以后，谁确定答案？ | AZR、R-Zero | 执行验证与共识伪标签 |
| 怎样训练一个裁判？ | Self-Taught Evaluators、GenRM、DeepSeek-GRM | 迭代筛选 SFT、生成式验证监督、评价任务 RL |
| 模型会回答，是否就会评价？ | Self-Rewarding、Meta-Rewarding、CoVera | 间接迁移、显式评价偏好、执行校准 |
| 两个模型都改善，是否一定双向闭环？ | V-STaR、ReST-MCTS* | 累积数据训练验证器，与验证器直接引导下一轮搜索不同 |
| 不改权重还算 D8 吗？ | DeepSeek-GRM、UCoE | 学判断参数与搜索评价程序都能改变评价能力，但机制不同 |

读论文时先画清反馈箭头，再问标签是否可信，最后看优化算法。这样即使后续出现新论文，也能定位它到底改变了哪个环节。
