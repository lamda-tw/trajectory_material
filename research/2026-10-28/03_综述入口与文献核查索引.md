# 综述入口、检索路径与原文核查索引

检索截止：2026-10-28。配套文件：[共同机制](01_D7与D8_循环流程与共同机制.md)、[16 篇论文拆解](02_代表论文的循环拆解.md)。

## 1. 这次怎样扩展了文献范围

先独立检索“模型自改进”“奖励学习”“奖励模型”“过程奖励”“推理自演进”相关综述，再按不同反馈来源和更新机制追溯原始方法；随后检索 2026 年的新工作，检查是否出现与已有分类不同的循环结构。

筛选原则是：

1. 核心方法首次公开时间为 2024 年及以后；早期算法可作为术语背景，但不充当本次代表论文。
2. 优先覆盖不同机制，而非把使用同一优化器的论文堆成列表。
3. 对较早工作，看其是否构成后续方法反复讨论的设计基础，以及是否有正式论文与可核查的实验对照；不把机构名当作正确性保证。
4. 对较新工作，看它是否增加明确视角；把“方法值得讨论”和“业务可靠性已经成立”分开。
5. 回到原文核对信号来源、训练对象、下一轮依赖关系；不根据摘要把缺失的箭头补成完整 RSI。

本次没有重新统计各论文的实时引用数，也没有获得企业内部部署数据。因此，“代表性”指机制代表性和公开文献中的关联，不能解读为引用榜排名或生产采用率。

## 2. 五篇重点综述，分别应该读什么

### S1. Self-Improvement of Large Language Models: A Technical Overview and Future Outlook

- **时间与版本：** 2026；本次采用 [arXiv v1 正文](https://arxiv.org/html/2603.25681v1)。
- **最值得读：** 整体生命周期框架；§3 的数据选择；§4 的模型优化，尤其 §4.2 Generation–Reward–Optimization。
- **分类贡献：** 将数据获取、数据选择、模型优化与推理改进放在同一个系统里，避免把自改进简化为“生成数据再训练”。
- **带着什么问题读：** 新模型到底在下一轮承担生成、选择、评价还是优化中的哪个角色？反馈有没有改变后续经验分布？
- **本次沿此视角展开：** SPIN、SCoRe、R-Zero、V-STaR、ReST-MCTS* 等不同的生成与优化方式。
- **边界：** 综述提供组织框架，不证明所有列入的方法都达到严格意义上的自主递归研究。

### S2. Breaking the Reasoning Barrier: A Survey on LLM Complex Reasoning through the Lens of Self-Evolution

- **时间与版本：** [ACL Findings 2025 正式论文](https://aclanthology.org/2025.findings-acl.386/)。
- **最值得读：** 数据演进、模型演进、自演进三个主体部分，以及搜索与反馈相关讨论；本次主要用于分类和文献导航。
- **分类贡献：** 将“产生更好的学习材料”和“更有效地学习”分开，再讨论两者如何循环。
- **带着什么问题读：** 表面上改进模型的论文，收益有多少来自搜索、题目或训练数据变好？
- **本次沿此视角展开：** 生成成功解法、搜索训练、过程模型辅助的自训练。
- **边界：** 重点是推理研究，不能直接代表全部 Agent 业务实践。

### S3. A Comprehensive Survey of Reward Models: Taxonomy, Applications, Challenges, and Future

- **时间与版本：** [2025，arXiv v1](https://arxiv.org/html/2504.12328v1)。
- **最值得读：** 偏好收集、§2.2 奖励建模及奖励使用分类。
- **分类贡献：** 区分判别式奖励、生成式奖励、隐式奖励，以及不同评分方式和粒度。
- **带着什么问题读：** 标签从哪里来？模型输出数值还是文字？奖励用于训练还是只用于选择？
- **本次沿此视角展开：** GenRM、Self-Rewarding、Meta-Rewarding，并结合后续 DeepSeek-GRM 分析生成式评价。
- **边界：** “奖励建模”涵盖许多单次训练组件，不应全部直接归为递归自改进。

### S4. A Comprehensive Survey on Learning from Rewards for Large Language Models: Reward Models and Learning Strategies

- **时间与版本：** [EMNLP Findings 2025 正式论文](https://aclanthology.org/2025.findings-emnlp.970/)。
- **最值得读：** Figure 2；训练时奖励的分类；推理时和回答后如何使用反馈。
- **分类贡献：** 将同一种反馈在不同阶段的作用分开：训练权重、生成时引导、生成后重排或修正。
- **带着什么问题读：** 一个系统效果提高，到底是模型本身学会了，还是额外计算帮它挑到了更好的答案？
- **本次沿此视角展开：** R1 与 GenRM 的差异、SCoRe 的多轮训练、偏好与隐式奖励。
- **边界：** 该综述引用了 2024 年以前的基础工作；本次只把符合时间要求的方法作为主要论文卡片。

### S5. A Survey of Process Reward Models: From Outcome Signals to Process Supervisions for Large Language Models

- **时间与版本：** 2025 年首次公开；本次采用 [2026-04-29 的 v3](https://arxiv.org/html/2510.08049v3)。
- **最值得读：** §2 如何产生过程数据；§3 如何构建 PRM；§4 如何使用 PRM；§7 的资源与能力权衡。
- **分类贡献：** 将过程数据来源、判别式/生成式等建模方式，以及推理搜索/RL 用途分开。
- **带着什么问题读：** 当前步骤正确性、未来成功可能性、任务进展是同一种标签吗？业务是否真的需要这么细的信号？
- **本次沿此视角展开：** Qwen PRM Lessons 与 ReST-MCTS* 的对照。
- **边界：** 综述中 PRM 一词覆盖的目标较宽；具体论文的标签语义仍以原文为准，不能仅按名称归类。

### 补充导航，未作为本次逐篇技术结论的主要依据

## 4. 本次特意避免的几种误读

| 容易出现的说法 | 原文核查后的表达 |
| --- | --- |
| 自改进就是上一轮权重继续训练 | Self-Taught Evaluators、V-STaR 的特定训练流程会重新从 seed/base 开始；递归也可以由数据与标注能力传递 |
| V-STaR 每轮用新验证器指导下一轮训练 | 原文明确的核心是迭代采集、累积正负数据及训练验证器；不能补成 ReST-MCTS* 那种搜索闭环 |
| 只要使用 reward model，就是 D8 | 固定裁判训练生成器，仍主要是 D7；D8 要看评价能力或评价机制是否被改进 |
| RL 的奖励需要可微 | 更新利用模型生成概率与奖励，执行器不需要可微 |
| 所有 PRM 都判断步骤是否逻辑正确 | 有些标签估计的是未来成功、搜索价值或进展；需要看定义 |
| 使用模型投票得到的标签就是可验证真值 | R-Zero 使用共识伪标签；应与执行验证分开讨论 |
| 生成式裁判写出解释，说明解释已经被监督正确 | 最终判定有标签，不等于所有解释 token 都具有独立正确性标签 |
| 两种角色共享模型，就是完全自主 RSI | 任务、奖励、优化器及迭代安排仍可能由研究者固定 |
| 更多推理计算提升了结果，就是模型永久变强 | 重排与多次验证可以不改参数；须区分任务内增益与跨任务能力变化 |

## 5. 建议阅读顺序

### 第一遍：先建立可复述的流程

读第一份文件的第 3、4、7、8 节。目标是能准确复述：被更新对象、信号来源、信号形式、更新方式、下一轮依赖。

### 第二遍：重点看六组对照

1. **R1 与 ETO**：强化学习和轨迹偏好训练怎样接收不同反馈。
2. **Self-Taught Evaluators 与 GenRM**：评价器自训练循环与生成式验证组件有什么差异。
3. **Self-Rewarding 与 Meta-Rewarding**：评价能力是否获得直接训练。
4. **V-STaR 与 ReST-MCTS***：累积失败数据与评价器引导搜索，耦合程度不同。
5. **Qwen PRM 与 ReST-MCTS***：步骤正确和搜索价值不能混同。
6. **AZR 与 R-Zero**：任务自动生成后，执行和共识分别提供什么依据。

### 第三遍：根据业务条件继续深入

- 有执行测试或仿真：优先结合 R1、ETO、V-STaR，再看 CoVera 的联合更新设计。
- 专家评价昂贵、开放回答较多：优先看 Self-Taught Evaluators、GenRM、DeepSeek-GRM，并先建立留出评价集。
- 需要多轮纠错：看 SCoRe；不要把一次正确答案 SFT 当作已经学会纠错。
- 暂时无法训练模型：看 GenRM 等评价器的推理用途，以及 UCoE 的离散评价程序思路；前者可以使用既有模型，后者仍需独立验证。
