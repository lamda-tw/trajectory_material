## 实验设置

从原始 Qwen3-8B 初始化新的 LoRA（r=8、alpha=16），不加载旧训练检查点，不复用旧首批轨迹或 Codex 评分。训练 seed 从 20261022 改为 20261026，作用于 LoRA 初始化、每轮题目顺序及派生的 rollout 采样种子。dev57 评估 seed 保持 100、temperature=0。Codex 外部评审没有可固定的随机 seed，属于保留的运行噪声。
每轮90题，每批5题，每题1条完整在线轨迹，轨迹结束后用原 Codex v7 prompt 逐步评分。仅 F=0 且 P>=3 做 SFT，所有 FAIL 均 mask；SDPO loss 与梯度必须为0。前5次有效更新 warmup 至5e-5，此后恒定，不使用学习率衰减。每轮18批，三轮54批；基础模型、数据划分、prompt、LoRA、优化器、loss归一化、上下文和生成参数保持原配方。

## 完成后的人工复核与下一步判断

复核时间：2026-10-27T20:41:55.019274+08:00。本次只读取并统计现有实验，未启动新训练或评估。

两次实验复现了“延长当前在线 ZeroFail3 SFT 会严重退化”的现象，但退化时间与表现不完全一致。新 seed 第二轮已出现 53.41% 重复文档动作、业务 API 步骤仅 131；第三轮进一步出现大量不符合执行协议的短回答。不能将新 seed 第三轮重复文档占比下降解释为纠正循环。

| 新 seed 的额外诊断 | 第一轮 | 第二轮 | 第三轮 |
|---|---:|---:|---:|
| dev57 因 no_python_code 终止 | 8/57 | 3/57 | 50/57 |
| 出现业务 API 的题数 | 54/57 | 32/57 | 10/57 |
| 训练采样中的无可执行代码步骤 | 16 | 12 | 21 |
| 上述步骤被标 FAIL 并屏蔽 | 16 | 12 | 21 |

第三轮上述 50 个 dev 终止回答均非空，长度 13–55 token，finish_reason 全部为 stop，没有 length；48 个不含任何代码围栏，2 个含围栏但没有可执行 Python 代码。训练中的 49 个无代码动作全部有 FAIL，ZeroFail3 入选数为 0。因此，目前没有“把大量无代码回答直接当正确样本训练”的证据。它可能是持续训练引起的行为/输出协议退化，但具体机制尚未通过因果对照确定。

例 b119b1f_2：新 seed 第一轮 13 步、6/6 检查通过，实际执行业务操作；第二轮 23 步中 18 个重复文档动作，0/6；第三轮 7 步后只用自然语言表示接下来要登录，没有输出执行代码，0/6。这个例子说明第三轮更短的轨迹也可能是更早失败。

54 次更新中 loss、梯度均有限，没有梯度裁剪，SDPO loss 恒为 0。学习率始终按原约定 warmup 后保持 5e-5。数值稳定不能保证行为稳定；现有证据不能断定学习率是唯一根因。

入选 SFT 样本中的文档动作占比仍为 62.37%、63.22%、57.84%，业务动作只有约 13%–16%。局部合规步骤被持续强化、但不足以教会推进和完成任务，是有数据支持的机制假设；尚未通过动作权重消融确证。第三轮平均 batch loss 从第二轮 0.14353 降到 0.06184，而任务成功从 8 降到 1，不能用训练 loss 决定是否继续。

建议停止对原恒定学习率配方做更多长轮次/更多 seed 的重复试验。仍值得做一次单因素、有限预算的学习率对照，用于判定减弱更新能否缓解退化：

- 优先从原 seed=20261022 第二轮 batch_036 的完整检查点分叉，其 dev57 为 12/57、Macro 58.41%；已有同一起点继续恒定学习率的第三轮作为对照。
- 只追加 18 批，恢复 Adam 和 RNG，不重新 warmup。学习率在这 18 次有效更新上从 5e-5 余弦下降至 5e-6，不重启；其余训练配置、第三轮任务顺序、派生采样 seed、rubric 与 ZeroFail3 路由保持一致。
- 数据仍由分叉后的模型在线新采样并评分；不会固定复用恒定学习率分支的轨迹。轨迹差异属于政策更新后的下游影响，Codex 评审仍有运行噪声。
- 中点 9 批和轮末 18 批各评 dev57；对照起点、原恒定学习率第三轮与衰减分支。中点评估不用于临时修改配方。
- 同时看整题成功、Macro、逐题得失、重复/纯文档动作、无代码终止和业务执行覆盖。仅降低循环占比或训练 loss，不足以判定改善。
- 如保住起点能力但未获得新能力，应描述为缓解/延后退化；若综合任务能力明显超过原恒定学习率第三轮且接近或超过起点，才值得下一步小规模复核。若仍严重退化，不继续做大范围学习率搜索，优先调整训练样本的动作权重或引入已验证的业务推进目标。
- 单次成功不能证明余弦形状更好：该曲线平均学习率为 2.75e-5，累计学习率只有恒定 5e-5 的 55%。这不是实际参数更新范数的精确比例；以后若需要区分形状与总更新强度，可用恒定 2.75e-5 作独立对照。

新 seed 的第二轮已经有严重行为退化，因此不建议从它的第二/三轮作为“预防退化”的起点。若后续要在新 seed 上复核，应从其第一轮分叉；本次不同时铺开两个分支。上述方案是讨论建议，不是新训练启动授权。

实现参考：[PyTorch CosineAnnealingLR 官方文档](https://docs.pytorch.org/docs/2.14/generated/torch.optim.lr_scheduler.CosineAnnealingLR.html)，支持不重启的余弦调度；具体起止学习率与预算是本实验设计选择，并非文档证明有效。
