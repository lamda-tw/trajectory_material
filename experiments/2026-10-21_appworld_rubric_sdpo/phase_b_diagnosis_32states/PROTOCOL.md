# B 阶段固定状态诊断（32 个状态）

本目录位于原 A/B/C 实验根目录下，独立保存诊断，不覆写阶段 B 结果。用户授权 GPU1 推理与执行诊断；**不训练、不执行优化器更新、不新增 Codex 调用**。

## 在模型推理前冻结的抽样

从 B 的 train90 历史轨迹与已有 v7-feedback 中抽取 32 个状态，任务全局不重复，dev57 不参与。四类各 8 个、每类来自第 1/2 轮的各 4 个：

- R6：反馈标记 R6 FAIL，且原动作是此前已有相同字面参数的纯文档查询。
- R1：R1 FAIL、有实际 traceback、无 R6 FAIL；允许伴随 R8。
- R8：R8 FAIL、无 R1/R6 FAIL，原动作为非认证业务 API。
- clean：ZeroFail、PASS>=3、无 U、非认证业务动作、此前未出现相同 AST 代码。

只纳入 target_step<=35、原 prompt<=22000 token 的状态，为 4 步执行留出空间。种子 20261024，以 SHA256 排名选取；较稀缺的 clean、R8、R1、R6 依次选取，每类先第 2 轮再第 1 轮。候选池、输入 token、原始反馈与来源 SHA 均冻结。各条件从新进程重放原动作，校验全部历史 observation、Python/数据库状态及 API 响应摘要完全一致。回放失败视为无效，不按生成效果换样。

这是有意平衡的机制诊断样本，不估计自然分布成功率；4 个类别也不是全体错误的穷尽分类。

## 对照条件与执行

- 初始 Qwen3-8B：32 个状态 C0；24 个 FAIL 状态 C2。
- 第 36 次更新后的 EMA 教师：32 个状态 C0；24 个 FAIL 状态 C2。
- 第 36 次更新后的实际学生：32 个状态 C0。

共 144 个分支。EMA 权重从既有 state.pt 精确导出；原学生导出权重也与 checkpoint 比对。C2 完全复用 B 的渲染器和反馈，不带原回答，首步 prompt_ids 必须与 B dataset.json 相等。干净状态不添加纠错反馈。

temperature=0、seed=100，保留原 3000-token 单步上限和 32000-token 上下文预算。每个分支最多执行纠错首步 + 3 个后续动作。C2 仅用于首步；后续用同一模型、原任务提示、实际新历史继续，避免把针对旧动作的反馈反复用到新状态。该短续跑是辅助诊断，不是完整任务成功率。

## 评估与概率诊断

分别记录：首步是否消除反馈指明的问题、是否产生新的执行错误、是否只是查询文档、后续 3 步是否使用信息推进业务、是否陷入重复。真实 API 响应与环境观察作为证据。自动指标只作行为统计，不能把任意业务 API 调用等同于正确进展；具体修复与进展采用逐例人工核查，可不确定则记 U。无独立新 Codex 评审，不把人工结论称为正式 rubric 分数。

在同一原始错误回答 token 前缀上，比较初始 C0/C2、EMA C0/C2、学生 C0 的概率；复现 B 的 student top100+tail reverse KL，并读取原 token 的 logit 梯度方向（仅对局部 logits 求导，无模型参数更新）。重点检查 API 动作选择和反馈明确指出的错误表达式，同时记录旧回答整体均值。整段原回答平均概率下降不能单独证明关键错误被压制。

判断框架：教师 C2 自由生成也无法修复，优先处理教师/反馈；初始教师可修复而 EMA 失效，优先冻结教师、防漂移；自由生成有效但旧前缀关键错误未得到纠正信号，优先评估“生成并执行验证纠正答案后再学习”的目标。即使诊断支持某分支，也不在本次启动新训练。

## 概率计算前补充：历史训练目标复算

除初始和最终模型外，对 24 个 FAIL 状态读取其原 batch 更新前 checkpoint 的 student/EMA teacher，使用完全相同输入重算 B 的 loss。对照保存的 step_metrics.json，记录数值偏差，并检查当时的原错误 token 梯度方向。该附加只读核对不改变抽样、自由生成条件或任何模型参数文件；不执行优化器或模型参数反向传播。最终模型探测与历史训练复现分别汇报。
