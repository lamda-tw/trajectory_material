## 3. 已完成：按确定的评分规则构建局部 SFT 数据

### 3.1 唯一入选条件

对全量 9,886 步计算：

S_step = sum(score(R_i), i=1..8) = #P − #F。

P=+1，F=−1，U=0，N=0；八个维度等权。**所有且仅有 S_step≥4 的步骤入选。** 不采用 P/(P+F)，不为凑满 30% 增补 3 分步骤。

| 阈值 | 步骤数 | 占全量 | 含至少一个 F |
| --- | ---: | ---: | ---: |
| ≥3 | 4,659 | 47.13% | 507 |
| **≥4：本轮采用** | **2,623** | **26.53%** | **106** |
| ≥5 | 863 | 8.73% | 13 |

精确前 30% 为 2,966 步，需从 2,036 个同为 3 分的步骤中选 343 个。采用 ≥4 保持同分同待遇，且比例接近原目标。该阈值根据本批标签分布确定，不依据本轮训练后的 DEV 成绩调整。

正式筛选清单覆盖 88 个任务、431 条轨迹；其中 41 步含 U，106 步含 F。R1=F 有 6 步，R4=F 有 34 步，R5=F 有 1 步（各集合可重叠）。这些步骤满足总分就保留，不再否决。净分是筛选启发式，不是正确率或已验证的学习价值；普通正向 SFT 会模仿入选目标的全部 token，F 的扣分不会变成负向 loss。

已完成的计算：[逐步总分与候选标记](/root/autodl-tmp/workspace-tw/experiments/2026-10-14_appworld_sft_init_step_rubric_v6_gpt61_sol/analysis/score_only_selection/all_step_scores.csv)、[阈值统计](/root/autodl-tmp/workspace-tw/experiments/2026-10-14_appworld_sft_init_step_rubric_v6_gpt61_sol/analysis/score_only_selection/summary.json)。正式筛选清单已生成于 [selected_steps.jsonl](/root/autodl-tmp/workspace-tw/experiments/2026-10-14_appworld_sft_init_joint_rl_local_sft/data/selected_steps.jsonl)，全量决定与入选集合经独立公式复核；清单对应的完整编码样本现已构建，见 [第 3 步记录](STEP_03_RESULTS.md)。

## 4. 第三步：把三个“轮数”分别确定

“每批 RL epoch=1”不表示整个实验只训练一轮。必须分别配置和记录：

| 名称 | 含义 | 本次建议 |
| --- | --- | --- |
| 在线采样轮数 | 当前模型遍历 train90、采样并更新的次数 | 拟定 5 轮；每批使用更新后的策略重新采样 |
| 局部 SFT epoch | 固定局部监督数据被完整学习的次数 | 拟定 5 遍；总监督量为 5×T_SFT |
| 每批 RL 更新遍数 | 同一批已经采样的 RL 数据被重复优化几遍 | 初始建议 1 遍，工程检查后冻结 |

### 4.1 为什么不把所有 epoch 都直接设为 5

SFT 是对固定监督目标重复学习。本次先固定 5 遍作为候选预算，保留第 1/3/5 轮评测观察学习过程；这不是对 5 遍最优或足够收敛的预先判断。

在线 RL 会在模型更新后不断生成新轨迹。每批只更新一遍、然后采下一批，也会在整个实验中产生很多次更新，不是只执行一次 optimizer.step。

如果同一批 RL 数据重复更新 5 遍，第二遍之后模型已经偏离采样时的行为策略。多遍更新可以提高样本利用率，但需要核对概率比、KL、clip fraction 和更新幅度；不能因为原来的 SFT 用过 5 个 epoch，就自动把每批 RL 也设为 5。

因此，当前建议是“5 轮在线采样 + 5 遍局部 SFT”，每批 RL 先按 1 遍设计。是否需要增加每批 RL 的更新遍数，应根据工程试跑与训练信号判断，不预设 1 遍一定充分，也不预设更多遍一定更好。

### 4.2 不再预填与本次数据无关的预算

筛选规则与 N 已确定；其余正式配置在数据构建和工程测量后补齐：

| 参数 | 确定依据 |
| --- | --- |
| N、T_SFT | 已实测 N=2,623，T_SFT=205,238；五遍 1,026,190 token |
| 每题新采样数 G | 候选 6；工程试跑核实成本后冻结，不根据 DEV 改动 |
| 每批题目数 B | 候选 6；核实轨迹长度、显存和梯度累积成本 |
| 每批 RL 更新遍数 K | 初始建议 1，结合策略偏移检查冻结 |
| 学习率、KL 系数、SFT 混合系数 | 本模型联合训练的数值与梯度检查 |
| attention、微批大小和并发 | 仅物理 GPU1；单进程/单卡，实测显存后冻结 |
| 随机种子与任务顺序 | 本实验独立记录，保证可复现 |

若在线轮数为 E=5，每轮每题采样 G 条，则正式训练采样数为 E×90×G。若每批 B 题、每次完整批次遍历后更新一次、每批重复 K 遍，则更新数为 E×ceil(90/B)×K；尾批按实际题数归一化。具体执行器若采用其他优化粒度，须按实现重新计算并记录，不能套用该式。

候选 B=6、G=6、K=1 时：每轮 15 批，5 轮共 75 次联合更新、2,700 条新轨迹。5 遍 SFT 对应 13,115 次完整原始目标消费。学习率 5e-6、beta=0.01、lambda=1 等候选及理由详见 draft JSON；这些是供审查和工程验证的起始值，不声称已测定最优。

局部 SFT 总监督量拟为 5×T_SFT。根据最终更新数编排消费计划，使五遍目标 token 完整覆盖；微批或 loss span 拆分只用于计算，不丢弃原始响应内容，不制造新动作；如使用 span 拆分，每段必须保留正确因果前缀，目标 token 不重计、不漏计。每个样本每遍恰好消费一次，不因提前耗尽或尾批而额外循环或丢弃。

**本步产物：** 写清全部实际数值的 training_config.json、预算表和 SFT 消费计划。正式训练开始前必须具体化；不能带着未填配置启动。

### 4.3 学习率跨轮连续衰减，不重新 warmup

候选学习率以全局联合 optimizer 更新编号计数：第 1—4 次从 1.25e-6 warmup 至 5e-6，之后连续余弦衰减，第 75 次到 5e-7。每轮结束不重置学习率、optimizer 或 scheduler；若总更新数改变，正式训练前重算调度并冻结。scheduler 的实际步号须通过测试与此约定一致。

RL 与 SFT 共享同一个 optimizer 的学习率。lambda 调节 SFT 梯度相对强度，候选为 1；本次不另设逐轮 SFT 学习率，也不把步骤分数作为 CE 权重。新联合运行从已有 LoRA 权重创建新 optimizer 状态，后续各轮连续保留状态。

历史五轮固定 2e-4 的结果出现退化，不能证明本次同样会退化或单靠衰减便能解决。五遍不是最优性结论；保留第 1/3/5 轮同协议评测，最终以预定第 5 轮比较，避免事后挑结果。数值候选仍需单卡工程检查，尚未启动训练。

4. 模型保存重载、推理权重刷新和断点恢复。

6. 采样、环境执行、训练和权重同步的真实耗时。

依据工程结果补齐第 4 节配置并冻结。若为排错进行过训练，正式实验前恢复初始模型、optimizer、RNG 与数据游标，试跑不混入正式训练预算。

**本步产物：** smoke_report、成本估算、冻结的完整配置。不能根据 DEV 训练后表现调参再冒充预设配置。

## 6. 第五步：建立训练前 DEV57 基线

在正式训练前，用初始 SFT checkpoint 完整评测官方 DEV57。保存每题轨迹和官方结果，核对 57 个任务身份和完整性。

推理协议依据本次目标模型的采集协议核对后固定，尤其明确 prompt、tokenizer、parser、thinking 设置、温度、随机种子、最大步数和上下文预算。训练前后评测使用完全相同的协议。

历史 DEV 成绩只作背景，不能代替新的同协议基线。DEV 数据和结果不作为步骤评分材料、SFT 目标或 RL 训练奖励。

**本步产物：** baseline_DEV57、官方聚合、逐题成功/失败清单。

## 7. 第六步：执行多轮局部 SFT + 在线结果 RL

### 7.1 训练顺序：先采样，再合并两种梯度更新一次

本轮采用**同步的 RL + 局部 SFT 联合目标**，不是先完成一阶段纯 RL 再 SFT，也不是先做额外纯 SFT 再 RL。现有模型已经经过 train90 epoch5 SFT，无需在第一批 RL 采样前额外预热。

每个正式批次执行：

1. 将当前 LoRA 参数 theta_t 同步到推理端，核对策略版本/哈希；同一批采样期间不更新参数。
2. 在 B 道 train 题上，每题独立采样 G 条新轨迹；保存该行为策略的实际生成 token、mask 和 old log-prob。旧 540 条轨迹不充当本批 RL 样本。
3. AppWorld 官方终态检查给奖励：完整成功为 1，模型造成的失败为 0；基础设施故障修复或重试，不作为失败奖励。
4. 在每道题的 G 条轨迹内计算相对优势；全等组优势显式为零，不删除整批或跳过计划中的 SFT 消费。
5. 清零梯度一次。在 theta_t 上，分别用本批新轨迹计算 RL/KL 梯度，用固定入选数据的计划批次计算局部 SFT CE 梯度。可为显存分开 forward/backward，但中间不执行 optimizer.step，不刷新模型参数。
6. 累积两部分梯度，正确归一化和加权后，统一做梯度裁剪、一次 optimizer.step 和一次 scheduler.step，得到 theta_(t+1)。本次仅物理 GPU1、world_size=1，核对单卡跨微批的有效 token 分母，不启用数据并行。
7. 保存/记录状态、策略版本和 SFT 游标；下一批采样前刷新推理权重。按预算完成 5 轮在线采样和固定数据 5 遍监督。

~~~text
当前 theta_t ──在线采样──> 本批 rollout + old log-prob + 官方奖励
     │                                     │
     │                               RL loss + KL
     └──固定入选步骤──> 局部 SFT CE           │
                         └────梯度相加───────┘
                                  ↓
                       一次 optimizer.step
                                  ↓
                              theta_(t+1)
~~~

因此，“先 RL 还是先 SFT”在这里需区分采样与更新：**先做 RL 采样；两种 loss 的计算先后可以按实现安排；参数只在两部分梯度都准备好后共同更新。** 先做一次 RL optimizer.step 再做一次 SFT optimizer.step 属于交替优化，会在不同参数点计算梯度、改变优化器状态，不是本计划的联合更新。

同一个已有 LoRA 副本承接两种梯度，不各训练一个 adapter 再合并。基础模型权重保持冻结，reference 为冻结的初始 SFT 模型；行为策略是本批采样版本，二者不能混淆。

训练目标：

L_total = L_GRPO + beta × L_KL + lambda × L_local_SFT。

L_GRPO 使用本批行为策略概率的 clipped ratio 目标；KL 的具体估计器、归约方式、beta、lambda 与学习率必须在工程检查后写入配置。RL/KL 与 SFT 分别按冻结的有效 token/组归约约定归一化，再相加；不能对各微批均值简单等权相加而随意改变长短样本的权重。

终态奖励的组内优势为：

A_i = (R_i − mean(R)) / (std(R) + epsilon)。

标准差约定与 epsilon 写入配置；全等组优势置零时仍计算预定 SFT 与适用的 KL。prompt 与工具观察没有 RL loss，SFT 历史不监督。步骤总分仅决定离线样本入选，不作为新 rollout 的 RL reward，不作为 CE 权重，也不变成负向 token loss。

默认每批 RL 更新遍数 K=1。若工程检查后改为 K>1，必须在正式训练前修订并冻结：每次 optimizer.step 都是当时参数上的联合更新；old log-prob 始终对应最初采样策略；相应重新编排 SFT 消费，使总量仍为 5×T_SFT，不能每重复一遍 RL 就无记录地额外重复 SFT。正式运行后不按 DEV 表现切换 K。

没有步骤级 RL 奖励时，不把轨迹优势说成已精确定位到错误动作。本实验回答联合流程及最终效果；没有纯 RL 对照时不能单独归因局部 SFT 的贡献。

### 7.2 新轨迹的评分与计时边界

训练期间新轨迹只运行官方成败检查，不再调用 Codex 做逐步评分。初始 540 条评分的标签作为固定监督来源，训练期不重写它们。

分别统计：

- 初始 540 条的外部评分调用、重试、token 和耗时。
- 数据分析、筛选与构造耗时。
- 新轨迹采样与环境执行、官方检查耗时。
- 模型训练、权重同步、保存和恢复耗时。
- DEV 评测、案例分析与报告耗时。

### 7.3 每轮检查与保存

每轮记录成功率、全失败/混合/全成功组分布、动作长度和终止类型；记录 RL loss、SFT CE、KL、梯度范数、概率比和 clip fraction。全等组不反复重采样直到成功，也不为制造优势临时改奖励。

保存每轮 checkpoint 与必要的 optimizer/RNG/数据游标。记录实际消耗的监督 token、实际采样数和更新数。出现 NaN、概率错位、错误权重加载或不可确认的断点时，先修复工程问题，再从可信状态恢复。

**本步产物：** 训练日志、完整新轨迹索引、每轮模型、预算与成本账本。

## 8. 第七步：验证最终性能并撰写报告

拟在第 1、3、5 轮分别完整评测 DEV57，观察学习过程；以第 5 轮相对于初始模型的结果作为主要比较，不挑中途最高分代替最终结果。

报告必须包含：

1. 流程是否完成：初始评分覆盖率、实际选样数量、联合训练和保存重载是否通过、是否达到计划训练量。
2. 训练前后 DEV57 成功数、成功率、差值，以及新增成功与退化的具体题目。
3. 训练曲线与第 1/3/5 轮评测，判断是否仍在改善、过拟合或退化。
4. 代表轨迹的实际变化，区分局部动作改善、任务完成改善与偶然成功。
5. 全部阶段成本，单列初始外部评分和后续在线训练。
6. 尚不能回答的问题：一次实验的提升不能单独证明局部 SFT 的贡献，五轮也不自动代表充分收敛。

若最终成绩没有提高，照实报告，不能将“能跑通”写成“有效提升”。若训练尚未完成，报告实际进度，不将部分结果写为完整实验。

完成本次实验后，再考虑使用相同起点和相同 RL 预算、去掉局部 SFT 的纯 RL 消融。本轮不预先执行该消融。

**本步产物：** REPORT.md、逐题变化表、过程曲线、案例分析和完整成本统计。
