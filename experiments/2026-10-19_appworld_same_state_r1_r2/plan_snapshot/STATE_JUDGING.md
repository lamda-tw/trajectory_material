# 同状态动作评价协议草案 state_probe_v1

状态：仅设计，未调用评委、未生成动作、未运行环境。第一阶段比较全规则SFT-1358、DropR1、DropR2；见 [实验设计](SAME_STATE_PLAN.md)。本文件在独立校准后、正式生成前冻结，不允许按哪组占优来修改规则。

## 1. 什么叫一步动作更好

一个动作是否有用，取决于它是否针对当前任务与已知历史做出有依据的推进，以及是否造成新的问题。不存在唯一标准代码；查询、核验、修改、计算或提交都可能正确。暂时不改变数据库的信息获取动作，也可能为后续成功所必需。

| 场景 | 有依据的好行为 | 不能据此直接判好/坏 |
| --- | --- | --- |
| API报参数错误 | 使用已给规格修正参数；若缺少规格，读取相关完整规格以解决问题 | 换个参数名字就算修复；执行又报另一种错误就认定旧问题没修 |
| 已读取对象及字段 | 使用正确ID/字段做必要查询或操作；发现时效问题时刷新状态 | 少查一次文档就算更好；直接操作就算推进 |
| 曾执行相同查询 | 在状态已变或有明确核验需要时重查；没有这些理由时改做有增量的动作 | 代码字符串相同就判无效；代码换了变量名就判有增量 |
| 分页/完整名单 | 根据可见规格与反馈继续补齐任务需要的信息，或明确指出尚不能下结论 | 读取了更多页就一定正确；没有立即得到官方通过就判无用 |
| 部分写入后报错 | 检查已生效部分，避免重复写入，再处理未完成部分 | 默认整块代码已回滚；只看最后一条异常忽略已有副作用 |
| 终止交付 | 答案和任务操作完成有可见证据，且符合协议 | 调用complete_task或诚实承认失败就等同任务成功 |

## 2. 前缀诊断卡：先于候选生成

卡片只允许读取任务公开指令、agent协议、此前真实消息和工具反馈。不得读取原当前动作、后续轨迹、官方答案/断言/最终成败，不查看候选组别。每张卡对9个模型共用，禁止根据某模型选择的动作增删机会分母。

每张卡至少包含：

```json
{
  "state_id": "task:before_step_k",
  "prefix_hash": "sha256",
  "known_facts": [{"fact": "公开可核对的事实", "evidence": ["history_step_2.observation"]}],
  "known_issues": [{"issue": "目前明确的问题", "status": "open|resolved|uncertain", "evidence": []}],
  "available_specs": [{"api": "app.method", "scope": "full|summary|unknown", "evidence": []}],
  "feedback_opportunity": "yes|no|uncertain",
  "state_use_opportunity": "yes|no|uncertain",
  "verification_needs": [{"need": "仍需核验的内容", "evidence": []}],
  "unknowns": [],
  "acceptable_action_families": ["多个可接受的动作方向，不给唯一代码或隐藏答案"]
}
```

“有反馈机会”要求可见历史确有待处理问题或有依据的重复/核验需求，不是单凭E/R机械标记；“有状态使用机会”要求当前可见信息支持下一步引用具体数据/对象/状态。仅凭S层的无异常执行也不能默认yes。诊断卡的事实、未解决状态及机会标记均需证据定位；缺乏证据时用uncertain。

卡片可由与动作评委分离的调用生成，先对8个独立校准状态做复核，再冻结模板；正式299张卡须在正式候选输出产生前完成。卡片错误的修订必须对该状态所有模型同时重评、保留旧版结果；不可只修改某一组的分数。卡片永远不提供给被测模型。

## 3. 候选的结构化判断

对每个状态×checkpoint保存如下字段，不输出合成“质量总分”：

| 字段 | 标签 | 判断要点 |
| --- | --- | --- |
| feedback_response | resolved / necessary_new_evidence / attempted_unresolved / ignored_or_repeated / uncertain / not_applicable | 指向卡片中的具体旧问题；resolved需当前证据，查询需必要且实际取得信息 |
| state_use | supported / contradicted / unresolved / no_relevant_use | 指出使用了哪些对象、字段、事实与状态；计划或明确待验证假设不当成既定事实 |
| meaningful_progress | evidence_gain / supported_operation / supported_completion / no_demonstrated_progress / uncertain | 多标签记录，不因动作长、调用多、数据库变化多自动判推进 |
| repetition | justified_refresh / no_information_gain / not_repeated / uncertain | 要比较历史及状态变化；完全相同代码只作机械辅助特征 |
| documentation | necessary / unnecessary_given_known_specs / missing_required_spec / not_applicable / uncertain | API摘要不等于完整规格；模型可复用此前已有完整规格 |
| termination | supported / premature_or_wrong / no_completion_claim / uncertain | 完成陈述与实际交付分别核对，不用调用成功替代任务完成 |
| new_execution_issue | absent / same_known_issue / independent_new_issue / uncertain | 独立记录，避免“修旧错又出新错”被压缩成一个标签 |

每个非not_applicable判断都要引用前缀/候选/当前反馈的具体证据位置，说明必要未知。`state_use=supported`并不自动表示任务已经推进；例如无必要地再次打印同一个正确ID，可以没有事实错误而没有信息增量。

主要二值统计从结构化标签固定导出：

- 在前缀feedback_opportunity=yes集合，`resolved`或`necessary_new_evidence`记有效反馈响应。只在文本中说“我会修复”但没有证据不计成功；合理但尚无可验证结果的动作单列attempted/uncertain。
- 在前缀state_use_opportunity=yes集合，公开证据支持的必要信息获取、合理任务操作或有依据的交付记有依据推进；另列state_use=contradicted事件率。
- 未执行代码、截断、模型导致的异常照常进入固定分母；必要信息读取可算有效响应，同时保留当前任务状态未改善这一事实。
- unknown不改写成F；主报成功事件/固定机会数，另报unknown率和unknown全成功/全失败的上下界。机会=uncertain的状态单列敏感性分析，不能悄悄当no处理。

### 三个需要防止的误判

1. **策略回避造成假提升。** 某模型不再做数据相关动作，R3=F率可能下降，但若推进率也下降，不能说状态使用更强。
2. **活动增加造成假提升。** 更多API调用、写操作或完成调用并不代表对象、范围、结果正确；必须结合实际反馈与evaluator。
3. **把方法类别当成质量。** 文档查询、重复读取、正常首轮推进（R6=N）都可能有用，不能因为研究假设关注R6而天然加分给恢复行为。

## 4. 辅助R1–R8与版本关系

辅助输出八维P/F/U/N，用于与训练选择分布对照，不以P总数定义胜负。定义来源为最新候选 [prompt_v7_en.txt](../2026-10-12_appworld_step_rubric/prompt_v7_en.txt)，SHA256为 `2eb29f25a4cc9a3bcf33c120e5f3c0bba092be42e06ad7b44b08a64157d91502`。它尚未完成语义验证，不能在正式评分前直接称为已验证标准。

`state_probe_v1`必须明确与原完整轨迹prompt的差别：

- 只评价当前一个候选动作，材料截止其实际即时反馈；不接原未来轨迹。
- 未知后续效果保持U，合理中间步骤不因尚未终态成功而判F；正常首次推进可以R6=N。
- 原八项定义保留版本来源，新增上述诊断字段和证据引用，不沿用原60字符短理由限制去挤掉关键证据。任何定义修订先记录差异、再在正式生成前冻结。
- 不能把当前后验v7标签与旧v6训练标签当成完全同一测量；原v6选择暴露和本次诊断行为分别报告。

按模型报告P/F/U/N全分布及F事件/全部共同状态；适用条件下的通过率只能辅助使用。R5/R7稀疏时必须给出适用数量，不强行对九个模型排序。

## 5. 盲评输入与证据隔离

拟沿用既有judge配置 `gpt-6.1-sol / high`。评分是后续实验的一部分，当前不得调用。每个候选独立提交，使用随机映射的checkpoint别名，隐藏组名、训练seed、目录、模型成绩与原终态。

允许输入：公开任务、协议、完整已有前缀、冻结诊断卡、当前原始响应文本、实际解析执行的代码、即时反馈。只执行首个Python块等原解析行为保持一致；未执行的额外代码在协议评价中仍需保留。不得让评委执行代码或访问文件/网络寻找隐藏答案。

禁止输入：该状态原第k步动作、原第k步反馈、原后续轨迹、新候选后续续跑结果、官方测试断言和答案、模型名/组别及已知分数。实际环境完整数据库不自动作为评委可见材料；不能用模型未知的内部内容证明某个推断当时已有依据。

如果即时反馈不能支持局部效果，保留U，之后用隔离的官方终态检查提供另一层结果。模型输入保持原token；仅评委材料可以作一致的凭证脱敏，并保持凭证之间相等关系与任务必需对象信息。所有九组用同一规则。

相同状态、完全相同候选文本/代码/反馈及卡片的证据哈希，可复用评分；各模型行仍保留，不能把重复输出当作更多独立证据。只因代码相同、但完成陈述不同，不得复用完整评分。

## 6. 复核与官方检查

独立校准只用计划中8个非正式状态；可用其已有原动作检查定义，也可在授权后最多生成3组×8个校准动作。校准用于发现歧义、漏证据或解析问题，禁止按组表现选规则。所有校准结果不并入299状态统计。

正式随机复核72条：每checkpoint主面板4条，加四个补充面板各1条，按固定SHA256盐 `20261019:judge_audit:<checkpoint_alias>` 排序选择，不依赖评分。报告原判、复核判、各字段一致率、unknown与修订原因；同一judge重新调用不称独立验证。明显分歧案例可以追加说明，但不能取代这72条随机样本。

官方evaluator另行读取隔离保存的before/after状态，报告相同requirement的0→1、1→0、净差及八类汇总；不能把尚未完成时的大量失败断言都归咎于当前一步。对合法只读动作，零即时终态增益允许存在；预选固定续跑阶段专门帮助判断这类信息是否能被利用。

原始前缀具有部分副作用，before不是干净任务初始状态。evaluator只作用于隔离副本，不让测试执行污染续跑状态或让被测模型看到任何测试反馈。

## 7. 必须保留的局限

评分还是有判断误差的测量，不能因采用相同八项rubrics就自证选样有效。单步反馈、行为盲评、官方即时检查和固定续跑各回答不同问题，需报告一致与不一致之处。即便三层都支持恢复改善，也只支持这些训练模型在这些状态上的行为机制；R6监督暴露的独立贡献仍需匹配训练干预。
