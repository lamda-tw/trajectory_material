## 完整结果分析：规则删除、选样变化与 evaluator 细项

分析更新时间：2026-10-19T20:41:53+08:00（北京时间）。本节只分析已保存的原始产物，未追加训练、推理、重采或评分。

**核心判断：DropR1、DropR2 是当前最值得复核的改善信号；DropR4 不能因整题成功率略升就判断有益；DropR6/R8 的结果有明显 seed 依赖；R5/R7 在本批评分与阈值下没有改变选样，因此无法从本实验识别其独立作用。** 这里评价的是固定数据、评分版本和预算下的选样策略，不是证明“执行正确、证据覆盖等要求不重要”。

### 1. 是否缺少“不删除任何规则”的基准

已从全部 11,254 步重新计算并逐个核对步骤 ID：**完整八规则 `P≥3 且 F=0` 的候选集合 = DropR5 集合 = DropR7 集合，共 1,710 步**。集合 SHA256 为 `715c06eed920c203b3169a2e7a92f29447a315aea8c9940a030e9ec7bf995ff9`。DropR5 的三个运行每次从这个集合均匀无放回抽 1,358 步，并从原始 Qwen3-8B 新建 LoRA，已经提供同预算全规则基准。

因此，不需要仅为增加 NoDrop/ZeroFail3 名称重训。若另起名字导致抽样随机流不同，得到的是同一选择规则的另一份重复实验，不是新的规则对照。DropR7 的选样、顺序、adapter 和评测别名哈希已复核，不能再作为三个额外独立重复。旧 1,710 步 ZeroFail3 模型不是本轮同预算基准。证据见 [baseline_equivalence.json](analysis_three_seeds/baseline_equivalence.json)。

### 1.1 Base、ZeroFail3 与 DropR5/DropR7：相同的是规则池，不是训练模型

**这里的“基准”应准确称为“全规则 SFT-1358 对照”，不能简称 Base。** Base 是未经本轮 SFT 的原始 Qwen3-8B；旧 ZeroFail3 是全规则池全部 1,710 步训练出的模型；本轮 DropR5/DropR7 是同一个池抽取 1,358 步的新模型，R7 复用 R5。候选集等价，不意味着不同训练预算的权重或成绩等价。此前只强调“不必补同预算 NoDrop”而没有并排展示旧 ZeroFail3，容易造成混淆。

**用户指出的下降成立。** 旧 ZeroFail3 平均 10/57，本轮全规则对照只有 5/57；Macro 低 9.48 个百分点，Micro 少通过 86 条。相对旧模型，本轮新增通过 105、丢失通过 191 条检查。三个 seed 的整题差为 −4/−1/−10，Macro 差为 −7.63/−1.52/−19.29 个百分点；前两次同在 GPU1 也下降，不能全归因于 GPU0。Base 的单次旧评测仅作背景，不作为三个 seed 的新重复。

**已排查的设置差异。** 两轮 `train.py` 完全相同；LR=2e-4、LoRA、优化器、loss、精度及最大长度等训练参数相同，同 seed 初始 adapter tensor 哈希也相同。评分 CSV、评分 prompt、agent prompt、DEV57 清单、执行 worker 的文件哈希一致；解码温度、评测 seed=100 与交互预算相同。评测入口的修改是读取新组名/seed、校验样本数与更新数；没有换评分标准。端口、adapter 名称、GPU0 UUID 处理属于运行隔离。

**确定发生的变化。** 每次减少 352 个不同步骤（20.58%）与 176 次更新（20.58%），目标 token 从 131,957 降到平均 104,703；旧 ZeroFail3 三次都看完整同一集合，本轮三次看到不同子集。子集采样和长度变化也改变训练顺序，第三 seed 的物理卡不同。因此，当前只能说“这三次从 1,710 全集到 1,358 子集的训练方案表现下降”，不能断言全部下降由少 352 步、某类样本遗漏或某一个规则单独造成。

全规则集合本身没有改变；本轮只是使用更少的样本训练。每个 seed 丢掉了少量原本就稀疏的 R5=P/R7=P 步骤，遗漏 ID 已保存，但不能根据它们与退化共现，就认定某条样本造成某个 DEV 家族失败。

**这不会取消本轮同预算对照的意义，但限制了结论。** “DropR1/R2 优于全规则 SFT-1358”回答固定 1,358 步预算的问题；它不是“所有删除方案都优于旧 ZeroFail3-1710”。例如 DropR2 整题均值略低于旧 ZeroFail3、细项 Macro 却更高。DropR1 的跨预算观察也较好，但要解释为删除 R1 的作用，仍应以本轮同预算对照为主。

#### 4.1 R1：减少低门槛文档步骤，同时放入执行失败步骤

删除 R1 移除 434 步，其中 352 步含文档调用；新增 109 步均有执行失败反馈，其中 **102 步同时被标为 R6=P**。这与评分定义相容：一步可以修复先前问题、但又遇到独立的新错误；R6=P 不保证本步成功。新增样本没有被语法/执行成功规则再过滤。

实际文档调用从基准平均 855.3 降至 695，R3=P 从 1022.7 升至 1310.3，R6=P 从 756.7 升至 1018.7；非文档 R3=P 从 478 升至 646、非文档 R6=P 从 291 升至 456。更合理的解释假设是：有限预算从容易得到 P 的文档步骤转向含状态处理与恢复证据的步骤，同时容纳了一部分局部执行错误。

**已知的是选样结构和结果都变了；尚不知道收益来自去掉哪些旧样本、加入哪些错误样本、它们的组合，还是相关的长度/顺序变化。** 当前不能说“执行失败样本本身有益”，也不能把 R6=P 当成已被验证的恢复能力因果中介。

#### 4.2 R2：主要是取消容易满足的 P 计分，不是大量放入错误证据

移除的 359 步全部恰好是 **R1、R2、R8 为 P**，其中 350 步含文档调用；新增只有 8 步 R2=F。每次选中这 8 步，仍有 1,358 步总量，所以本组的主要结构变化是从门槛上移走简单文档读取步骤，再提高其余样本的抽取概率。

实际 R2=P 总量反而从 1249.7 降到 1208，但非文档 R2=P 从 396 升到 498；R3=P/R6=P 也增加。这支持“当前三 P 计数可能过度奖励简单读取，而删除一个容易获得的 P 会间接提高其他正向证据的密度”的选择机制。它不证明证据与覆盖这项能力没用。尤其 d4e9306 的完整并集检查从 1/9 降到 0/9，不能把总体改善等同于全面改善覆盖。

DropR2 的候选池仅 1,359，每次只舍弃一条，三个 seed 两两共享 1,357/1,358 个步骤；而基准只共享 1,075–1,089 步。因此 DropR2 看起来更稳定，部分也可能因为它的抽样组成几乎固定；seed 仍同时改变初始化与训练顺序，不能把稳定性归结为评分本身。

#### 4.3 联合分析 DropR1/DropR2：共同的预算重分配，比单独归因 R6 更有依据

补充核验时间：2026-10-19T20:41:12+08:00（北京时间）。已核对 540 条原轨迹哈希、候选 ID 及三个 seed 的实际训练步骤；仅 CPU 分析，没有改变训练样本或启动实验。

**更新判断：两组共同排除一批只靠 R1/R2/R8 三个 P 入选的步骤，提高 R3/R6 正例的训练暴露；R6 是重要候选解释，但现有比较没有分离 R3、R6、文档调用与具体内容的作用。** DropR2 并不需要大量新增执行失败候选就能获得改善；不能把两组的共同收益都归因于 DropR1 独有的 109 条执行失败样本。

| 在共同移除之外，再移除 | 75 | 0 |
| 新增 | 109 | 8 |

**共同移除的 359 步究竟是什么？** 全部恰好只有 R1/R2/R8 为 P，R6 全为 N；R3 为 354 个 N、5 个 U，没有 R3=P。350 步含文档调用，其中 show_api_descriptions 为 200 步、show_api_doc 为 124 步、show_app_descriptions 为 26 步。它们可以是合法、有用的读取，N 不是差评；当前证据支持“有限训练预算可能给这类步骤过多曝光”的假设，不支持断言这些步骤本身错误或应永远排除。

**DropR2 的 R6 富集主要来自重新分配预算。** 它保留了原池全部 945 条 R6=P，仅新增 2 条，候选 R6=P 从 945/1710（55.3%）变成 947/1359（69.7%）。在固定 1,358 步预算下，原有正例被选中的比例提高。DropR1 则额外移除 75 步（其中 68 个 R6=N、7 个 R6=P），新增 109 步（其中 102 个 R6=P）。二者不是同一种新增样本路径。

**两组高度重叠，不能视为两份独立的 R6 因果验证。** 候选共有 1,276 步，占两组各 92.1%/93.9%；实际同 seed 训练步骤交集为 1248 / 1250 / 1250，约占各组 92%。它们更像在很接近的共同样本上做少量不同替换。

**输出行为与 evaluator 是否也共享改善？** R1/R2 在 19 个家族中共同有 14 个 Macro 高于全规则对照；同 seed、同题、同断言相对对照共同新增通过 122 条，另分别独有 102/54 条新增通过，也共同丢失 26 条。检查项不是独立样本，这只是收益分布的描述。

**下一步优先级随之调整。**

1. 共同状态比较必须同时纳入全规则、DropR1、DropR2：预先区分反馈/恢复状态和普通读取/状态使用状态，观察两组是否都减少无效重复、是否正确利用状态，以及收益是否集中在恢复场景。保持相同输入与可恢复的执行环境，仍报告完整 evaluator；诊断分组不用于训练过滤。
2. 若追加训练，优先检验共同的选择机制：将全规则池与“仅移除这359条三P组合”的池比较。后者有1351条，新增任何F候选都不需要；可统一1350步、1轮、同初始化seed重新训练两组。移除谓词只由评分定义，不能用实际文档调用或执行结果过滤。这个实验检验该样本替换策略，不单独识别R3/R6作用；不能直接复用现有1358步模型作为1350步对照。
3. 如果目标仍是单独检验R6，沿用上一轮提出的评分配对实验：两组各1358步，共享1158步，另200步以R6=N/P配对替换、其余七项评分完全相同，得到700与900个R6=P。它更直接控制R3评分分布，但仍不控制内容/任务/长度。与上一个两组实验择一优先，不需要同时铺开全部消融；另做R3匹配对照可作为后续，而非现在就把收益归给R6。

更新后的研究假设是：**当前三P阈值使一批正常执行、有效读取、符合协议的步骤占据较多训练预算；移除其中任一计分来源后，共同减少这批步骤，增加带状态使用与反馈处理证据的样本暴露，并可能改善任务推进。** 已确认的是集合与暴露变化；“恢复学习导致成功提高”仍待验证。

依据：[联合统计与R2新增样本](analysis_three_seeds/r1_r2_joint_analysis.json)、[全部相关候选成员及原轨迹路径](analysis_three_seeds/r1_r2_candidate_membership.csv)、[复算脚本](scripts/analyze_r1_r2_joint.py)。本节所有选样分析沿用冻结v6评分，不混用之后的prompt版本。本次没有追加训练或修改正式执行计划。

#### 4.4 R3、R4、R6、R8 与无法识别的 R5/R7

- **R3：轻微正向线索，证据不足以建议删除。** 移除 68 个无文档调用的原样本，新增 29 个 R3=F 候选（19 个含文档调用）。Macro 三次均略升，但 Micro 第三次下降、家族改善不广、描述区间跨零。不能得出“数据忠实性不重要”或“该规则普遍有害”。
- **R4：没有总体收益证据。** 仅移除 2 步，新增 50 个决策/计算 F 候选，实际选中 37–41 个；前两次的整题、Macro、Micro 均退化，第三次反转。选择与结果都提示需要警惕内容、范围要求的损失，不能依据平均整题数就删掉它。
- **R6：大幅放松 F 排除，但平均小收益不稳定。** 新增 675 个候选、其中 530 个含文档调用；训练选中 368–384 个 R6=F，R6=P 从平均 756.7 降至 545.7。前两次 Macro 都低于基准，第三次高很多。它同时改变重复/恢复行为与抽样覆盖，当前不能确定收益方向，也不能断言“重复错误样本有益”。
- **R8：显著改变训练行为分布，效果与协议代价需要分开看。** 移除 432、加入 1,268 步，新增中只有 1 步含文档调用；实际约一半样本带 R8=F。文档调用降到平均 385.7；R5=P 从 2.3 升到 34，R7=P 从 0.7 升到 14.3，直接出现 `apis.supervisor.complete_task(` 的目标由 0 升为平均 15 步。更多业务操作与终止监督可能与空答案/局部内容改善有关，但集合覆盖未改善，无代码终止也增加。不能把 R8 的全部 F 简化成未查文档，更不能仅据终态成绩认可违反协议。
- **R5/R7：当前没有选样干预，无法估计独立效果。** 其 P 都不决定三 P 门槛，其 F 没有独占排除任何原本符合其余七项条件的步骤。数据里 R5=P/R7=P 原本只有 4/1 步，极稀疏；这可能是当前轨迹、适用性及共现造成的不可识别，不是“动作效果/终止交付无用”。继续在同一数据和阈值上重复 DropR5 对 DropR7 不能解决这个问题。

等步数控制了 1,358 个样本与 679 次更新，但不控制 token、上下文和算力。目标 token 相对基准：DropR1 约 +6.0%，DropR2 +3.3%，DropR8 +25.8%。本训练 loss 是逐步骤平均目标 CE 再平均步骤，因此更长响应并不自动获得更多整步 loss 权重，但监督内容与计算量确实变化，不能剥离为纯“规则语义”的贡献。

### 7. 补充实验建议：先回答具体疑问，再决定算力投入

**不优先补一个同预算 NoDrop 名称。** 现有 DropR5 就是同样选择规则的三个新模型。若担心基准方差，应把额外算力用于预先固定的新重复，并同时运行待比较组；只多训基准会让配对不齐。

1. **确认 R1/R2 的收益是否可重复。** 选全规则/DropR1/DropR2，新增三个预先锁定的 seed，例如 20261018/19/20，每组仍 1,358 步、1 epoch，共 9 次训练。报告整题、Macro、Micro、八类检查及逐 seed 方向，不能只保留最好结果。当前数据筛选沿用同一冻结评分版本；若采用新版评分 prompt，需所有比较组统一重新定义评分池，另列实验，不能混进本轮重复。优先固定在同一张卡以减少设备混杂；若两卡并行，预先平衡组和 seed 的分配。此建议没有启动。
2. **解释 R1 的两条选择路径，做 2×2 拆分，比再加一个 NoDrop 名称更有信息。** 四个条件分别为“P 计分保留/删除 × F 排除保留/删除”，即全规则、只取消 R1 的 P 计分、只取消 R1 的 F 排除、完整删除 R1；候选数依次 1,710/1,276/1,819/1,385。统一 **1,276 步、1 epoch、638 更新、3 seed**，共 12 次训练，四组均新训；现有 1,358 步模型不能直接充当此预算的对照。全程仍只由评分确定候选、全池均匀无放回抽样，不按语法、执行状态、动作类别或题目加门槛，也不靠重复或补足凑数。
3. **若优先研究 R2，同样四格的最小池是 1,351，可取偶数预算 1,350 步、675 更新。** 四格池为 1,710/1,351/1,718/1,359。也需同预算新训全规则及其余三组。若打算一起研究 R1/R2，则共同统一到 1,276 步，七种不同条件 × 3 seed = 21 次训练，可共享一个新全规则组。两条路径可能有交互，不能把拆分效应预设为相加。
4. **学习机制主线仍是已有模型的相同状态诊断。** 使用原计划冻结的状态清单，比较同 seed 的全规则、DropR1、DropR2 等模型下一步输出、执行反馈、证据获取、恢复与交付行为；每个模型看到完全相同的历史 token 和恢复环境。重点检验“是否从重复文档查询转向有效业务操作”，并保留执行错误、无代码和所有失败。这个实验直接复用已有模型，无需先追加 SFT；它能补上自然 rollout 状态不同的缺口，但一步行为变化仍不自动等于任务成功的因果中介。
5. **R5/R7 需要新的可识别数据条件。** 若要评估这两项是否有效，应先获得足够实际修改/交付的轨迹，并确认保留/删除该维度会改变合格步骤集合；同一冗余池上换更多 seed 无法识别它们。新数据所有比较组共享、仍仅按评分选样。若要回答“优于随机选样”，另加同 1,358 步预算的 Random；它解决的是选择效果问题，不能替代上述机制实验。
