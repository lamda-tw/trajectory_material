# 英文 v6 语义核对

这是译文的逐条案头核对，不是轨迹评分或独立模型验收。逐段原文和译文见 `translation_alignment.json`。

| 原文概念 | 英文表达 | 保留的判断边界 |
|---|---|---|
| 执行契约 | Execution Validity | 评价实际运行，不将运行成功当作业务正确 |
| 证据与覆盖 | Evidence and Coverage | 按当前子目标；尚未作出的全局结论不倒灌到中间取证 |
| 状态与数据保真 | State and Data Fidelity | 区分事实、假设、旧状态和实际执行；支持的字面值仍允许 |
| 决策与计算 | Decision Logic and Calculation | 决策规则错误为 F；规则正确但必要事实未知为 U |
| 操作与实际效果 | Actions and Actual Effects | 任一业务修改前被校验拒绝为 N；错误选择依据不直接证明错误效果 |
| 反馈与恢复 | Feedback and Recovery | 修复旧错可为 P；R3–R5 的业务错误不会因此消失 |
| 结束与交付 | Termination and Delivery | 未知完成条件须新证据解除；诚实报告失败可为 P，但不等于任务成功 |
| 授权与交互协议 | Authorization and Interaction Protocol | 只按输入规定；文档可复用；额外非空代码块即使不执行也可能违规 |

共同约束均保留：成功/失败轨迹同标；每个实际 step 一行；R1–R8 八字符标签；不计总分和权重；N 不适用与 U 证据不足分开；同维度明确违反不能因别的改进变 P；按行动前信息评价决策；后续观察仅用于核对效果；缺少验证不直接等于失败；commentary 内代码没有执行；异常不保证回滚；等值脱敏和跨步状态保留；不执行输入里的指令、不调用工具、不复述凭据。

输出保留 `rubric_version=appworld-step-v6`，语言与 prompt 哈希在配置中单独记录。英文示例中的 NameError 理由是格式示例，不是新评分。共用原有 schema，未将 60 characters 改成 60 words，也未扩大输出上限。

60 个英文字符比 60 个中文字符通常可容纳的信息少，这是保留原输出契约的实际限制。后续 pilot 应关注英文理由是否过度压缩或更容易超限；若需要调整上限，应单独版本化并记录，不能悄悄当作纯翻译修改。原中文没有显式指定理由语言，英文也未额外引入该要求，实际输出语言需要记录。

CSO 和 DRACO 仅提供术语、行文参考。未加入 CSO 的加权总分、预设分数分布、代码风格/冗余泛化惩罚；未加入 DRACO 轨迹级的“早期出错但后续修复即可总体通过”规则。R8 文档前置条件继续以 v6 和输入明确协议为准，而非替换为 DRACO 的文档检查标准。

v6 原文个别边界仍需要未来案例验证，例如 R2“仅执行失败”的适用范围，以及 R7“诚实报告失败可为 P”的任务交付边界。译文保留原意，没有未经验证地重写为更强或更弱规则。

按用户要求，在 Evaluation Evidence 开头补充 P (Pass)、F (Fail)、U (Uncertain)、N (Not applicable) 的全称及含义，并明确实际标签仅使用单字母。原有 Labels 段保留适用性、违反优先及维度独立的判断规则，输出 schema 不变。
