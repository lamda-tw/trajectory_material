# 校准审阅与正式阶段边界

审阅发生在正式129状态的任何候选动作生成之前。研究助手查看匿名状态、完整候选、即时反馈及评委证据；没有以模型组的胜负选择模板。此审阅不是独立人类金标准，也不提供评委准确率。

技术检查：138个输入逐token一致；9个校准前缀各独立重放两次；3个本地状态传输探针；27个固定校准首步；9个最多3步的技术续跑分支均通过。被动 API 返回记录再用相同27个输出重放比较，观测、请求、前后完整指纹完全相同，没有新模型生成。写入探针只证明状态隔离与异常副作用传输，不证明任务得分改善。

使用两版校准，共18次前缀卡请求、54次动作请求（72个逻辑评分请求，另有有界传输重试）。正式使用第二版。保留所有原判，不用多数投票改分，也没有第三轮调参。

## 第一版发现及第二版处理

1. `state_46de7671f22caf17df37` 的三个匿名动作都成功点赞已知歌曲266，但缺少 `like_song` 的必需完整规格。第一版 `grounded_application` 出现2个yes、1个no；第二版明确计划原有“不能跳过必要规格”的要求，三个均为no。局部效果仍可获R5=P，并可以真实改善evaluator；两者不混同。
2. 凭证直接作为纯文本打印时，旧脱敏规则存在遗漏。5份已发出的校准输入含AppWorld模拟密码，详见脱敏事件审计。补充57任务仅本地使用的模拟凭证替换表后重新评分；这些值只用于删除敏感文本，不作为新证据加入请求。正式评分要求该表存在并通过回归检查。
3. 第二版对 `state_1994a280d624c73e9bab` 的B机会判yes，对三个首次读取真实密码的动作均判B=yes。接受此解释：已知完整且无参数的凭证读取接口确实获取新的任务准备信息；它区别于只执行登录或重新打印已知凭证。第一版将这类首次读取也排除，过于狭窄。**因此B包含有依据的新凭证读取，不能把B的提升全部解释成业务对象处理改善。** 报告需结合真实API类型和后续evaluator说明，不把认证准备等同于任务完成。此边界在正式输出前记录。

## 自然动作未覆盖的边界：公开人工小例子审阅

以下是研究助手对判定定义的逻辑检查，不是新增正式样本、额外评委请求或模型准确率测试。

- 仅获得接口名称列表：缺入口时可算A的发现；不算完整规格已获得。已有列表再读不增加信息。
- 已知分页规格且实际令牌可用，第一页满页、无总数或结束证据：合理读取下一页且收到新对象或有效空终止页，可以是C进展；随意加页数、重复第一页不自动成立。
- 已有完整缓存或可靠总数覆盖全部对象：可依据缓存完成核验；不能为了得到C正例强制继续请求分页。
- 有规格而无必需输入：该业务调用没有B机会；另一个无参数且完整指定的凭证读取可以有自己的B机会。登录成功本身不等于新的业务证据。
- 复合动作先写入再报错：保留已发生的局部效果，同时记执行错误；不能整步回滚或把该步所有效果填零。
- 代码正确而叙述说“刚才是语法错误”：叙述矛盾和代码状态误用分列。
- `complete_task` 返回成功：不能直接认定任务成功；须检查本地官方断言。诚实失败报告也不是成功完成任务。

## 正式阶段冻结规则

129个状态、20个续跑状态、9个权重、54个复核位置不改动；不按校准表现补选状态。正式卡片先于候选生成冻结。评分只看获准的脱敏公开前缀、卡片、候选完整文本、实际代码和即时反馈；被动记录中未打印的返回数据及官方evaluator只在本地审计。

新增的断点采样辅助器已经用非模型测试核验：第一次有效输出必存盘；重启不能清空三次传输重试预算。有效输出不会因为评分差、执行报错或终止而重新抽取。正式统计代码与非平凡任务权重/配对符号测试一起冻结。最终仍报告小样本、状态选择、接手策略和有限续跑预算的适用范围。
