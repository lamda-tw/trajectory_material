# ZeroFail3、Random、Net3：信息获取、行动转换与范围覆盖的同状态实验

2026-10-20（北京时间）。**状态：仅计划与已有文件的 CPU 索引核验，未获本实验执行授权。禁止启动训练、GPU 推理、AppWorld 重放、外部评分或续跑。未来本地 GPU 工作仅使用物理 GPU1。** DropR1/R2 后续工作暂时搁置；本目录是新的独立设计，不修改其完成结果。

## 1. 要回答什么

当前证据是：旧1710步实验中，ZeroFail3三个seed总体均超过Random/Net3；自然轨迹中错误与重复减少、部分任务的集合覆盖改善。但Net3执行错误更少却没有同等收益，ZeroFail3也没有逐题或逐项支配其他策略。待检验的机制是：**模型是否更能根据当前信息缺口，及时取得必要信息、在资料足够时采取有依据的行动，并在任务需要完整范围时继续补齐证据。**

本次估计“固定历史与环境，替换已训练模型权重，如何改变下一步及共同后续策略下的结果”。既不把高P总数定义为胜利，也不预设ZeroFail3一定更好。训练标签为旧冻结v6；后验诊断以当前v7定义及新机制字段为依据。两者不是同一种测量，不能直接相减。

| 预先提出的假设 | 支持证据 | 削弱该解释的结果 |
| --- | --- | --- |
| H-A：缺少关键规格时能有效补足信息 | 在共同前缀机会集合上，更常真正获得相关缺失规格，少猜接口/参数，少做无关查询 | 只是文档调用更多，必要缺口未减少或反复查已知内容 |
| H-B：资料足够时能转向有效行动 | 更常正确调用接口取得新任务数据、完成必要计算/操作，少重复已有文档 | 重复减少但错误增加，或缺规格时冒进；有依据推进不升 |
| H-C：需要完整范围时能处理分页/多来源 | 正确推进未完成的范围检查，覆盖对象更完整且不过度纳入无关对象 | 仅多读数据但不正确利用；已完整仍继续取数；越界或错误提交增加 |
| H-Y：上述动作差异具有后续价值 | 各来源、seed和固定接手策略下，有限预算内的相关官方细项或达成率有一致改善 | 行为指标提高但后续效果持平/退化，或优势仅在单一接手策略/旧收益家族 |

恢复、核验与交付仍记录为辅助行为，不将本次再次变成泛化R6平均分排名。因DEV57已多次分析，所有结论属于机制探索；确认性泛化仍需新任务。

## 2. 比较对象与控制条件

旧策略定义：Random在全部候选步中均匀抽样；Net3要求P−F≥3；ZeroFail3要求F=0且P≥3，P/F为旧冻结v6八项中的PASS/FAIL计数。原训练不另加语法、执行成功或题目配额过滤。

采用 [models.json](models.json) 中九个已保存adapter：Random、Net3、ZeroFail3，各seed 20261015/16/17，均1710步、1 epoch、855次更新。九个adapter文件已核对训练完成记录中的SHA256。全规则1358/DropR5、DropR1/R2、旧Base的额外候选生成、Pass4/HighFail3、新SFT/RL均不在本次范围。

每个被选状态交给全部九个模型；按同训练seed、同状态比较ZeroFail3−Random、ZeroFail3−Net3，Net3−Random为辅助对比。三个seed是三个已训练权重，不是在同一个模型上随机采样三次。源轨迹seed与被测权重seed是不同字段。

推理保持历史agent提示词、示例、代码解析和停止协议；temperature=0、top_p=1、top_k=−1、repetition_penalty=1、enable_thinking=False；32000上下文，输出预算min(3000,32000−实际输入token)，生成seed=100+(原绝对step−1)。下一步及续跑都沿用该绝对step规则。**agent输入不能加入诊断卡、选择规则、组名、额外纠错提示或隐藏测试。**

最新后验规则采用`plans/2026-10-12_appworld_step_rubric/prompt_v7_en.txt`的八项定义，SHA256见[protocol_manifest.json](protocol_manifest.json)。新机制模板先在独立校准集确认、再冻结；不能因为某组占优修改定义。先前代理提示词不同时升级，否则不能再逐token复原旧状态。若未来用户明确要升级agent提示词，必须另立版本并对所有组一致处理。

“候选机会”不是人工确认的正确场景。例如“how many”可能只需读一个汇总字段，未必需要分页；取得规格也未必已有认证信息。这些由正式生成前的盲诊断卡判定为yes/no/uncertain，九个模型共享同一标签。不适用、未知和恢复失败都不能靠换样补齐。

具体ID、来源文件、原轨迹SHA256、替换步号、输入token数、前缀哈希已写入 [states_selected.csv](states_selected.csv)。人类可读清单和完整算法见 [STATE_SELECTION.md](STATE_SELECTION.md)；全部候选见 [state_inventory.csv](state_inventory.csv)。

相同前缀跨来源可能重复，只保留一次正式状态，所有出处保存在 [selected_prefix_provenance.json](selected_prefix_provenance.json)。来源配额按选中出处记账；实际输入使用同一真实前缀。评委用`public_state_id`（前缀哈希生成的不透明ID），禁止传含来源组名/seed的研究者ID。

## 4. 怎样保证同状态

每个状态保留原始初始消息以及前k−1步真实assistant文本、执行代码和反馈；重建消息必须逐token等于原第k步保存的prompt_ids。当前只核对了保存的哈希，尚未重新分词验证。

每个候选在隔离AppWorld中重放全部实际前缀代码，包括异常和异常前的部分副作用；恢复Python变量、数据库、文件、任务状态、时间、随机状态和请求追踪。完整指纹在独立重放与分支之间必须相同，逐步反馈必须匹配原日志。原自然轨迹未保存完整会话快照；因此这是日志一致性与独立重放一致性的验证，不能仅凭反馈哈希声称已经证明所有未记录状态完全复原。数据库快照只供evaluator使用，**不能用数据库load_state代替Python会话恢复**。

沿用上一轮已修复的SQLite full backup、完整表内容核对和文件哈希去重。FTS影子表也继续严格核对，不再通过SQL变更日志重建评测快照。evaluator在独立进程、副本上工作，绝不把评测反馈或隐藏答案交给policy/评委。

正式状态一旦恢复不可靠，标记基础设施缺失、报告共同可比较覆盖，禁止补零或替换。模型自己的语法/API/认证异常、无代码、上下文耗尽照常计入结果。已有有效输出不重采到成功；基础设施请求同参数最多3次技术尝试，保留全部日志。

5个正式状态输入超过29000token，最大30286，最小响应预算1714；照常保留。不截历史、不增窗口来改善结果。后续一旦上下文耗尽，按原协议终止，并计入预算损耗。

## 5. 评价与分析

详见 [ACTION_EVALUATION.md](ACTION_EVALUATION.md)。三层证据分开：真实执行、公开证据的盲行为判断、官方evaluator。A/B/C各有一个主要机制指标，附固定分母下的重复、执行错误、状态矛盾、范围越界、错误交付与token代价。R1–R8作为辅助全分布，不合成质量总分。

各场景和57题参照分开报告；不把定向面板混合成新的DEV成功率。主比较同状态、同训练seed配对；来源三组等权，题目在来源内等权，三个被测训练seed等权。相同前缀不重复增加样本量。C同时列出两种子类型；d4e9306结果与排除该发现家族后的结果分别报告。

卡片机会=no/uncertain仍公布数量和动作分布；主率分母为共同yes状态集合，unknown行为不删分母、不自动判F，给出unknown占比及上下界。若某面板yes状态不足12个、任一来源不足3个，或独立任务家族不足6个，按预定规则标“覆盖不足，仅描述”，不宣称确认机制，也不另抽状态。阈值是本设计的报告门槛，不是统计功效保证。

三seed均值与方向、每来源差异、19家族分解一并给出；家族聚类bootstrap只作描述性区间，不能把1161个动作或数千条断言当成独立重复。初始比较已有方向预期，仍报告负结果，不能按胜负改指标。

## 6. 后续效果是核心阶段

[continuation_states.csv](continuation_states.csv) 已固定20个正式状态：18个核心状态（场景×来源各2）及2个专门复查d4e9306旧发现的状态。后两者单独报告，不与核心结果混为新的总体估计。

每个状态的9个第一步动作全部保留，分别交给三种**固定共同接手策略**：Random、Net3、ZeroFail3的seed20261015权重。每一种接手策略都接手全部9种首步，不能让每组只由自己继续。这样能观察接手策略依赖，避免只用旧Base这一弱策略掩盖信息价值；三种接手策略也不能按结果挑一个报。

20×9×3=540个分支，每分支最多12个额外模型步，总上限6480次后续生成。首步来自阶段一，不重新生成。比较第4和第12个接手步（或更早终止时保留终态）的官方细项及行为代价，具体流程见 [CONTINUATION_AND_BUDGET.md](CONTINUATION_AND_BUDGET.md)。

这回答“替换第一步，在固定后续策略与有限预算下会怎样”，不等于已证明自然整题收益全部由此中介；也不单独识别训练中R6、R8或某类文档样本的贡献。12步结束时未完成只能称“此预算内未达成”，不能说永远失败。
