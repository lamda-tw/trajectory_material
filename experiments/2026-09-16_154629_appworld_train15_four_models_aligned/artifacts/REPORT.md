# AppWorld Train-15 四模型对齐诊断报告

> 本报告评测的是与 SFT 数据重叠的 15 个训练内任务（5 个 scenario × 3 个变体），用于判断模型是否学会训练轨迹；它不是未见任务泛化分数。固定 temperature=0、seed=100、max_steps=50，并使用官方 evaluator。

## 核心结论

LoRA epoch5 在训练内取得 4/15 TGC（26.7%）与 43/84 断言（51.2%），明显高于 Base 的 1/15 与 32/84，说明这些轨迹并非完全不可学；但四个成功集中在前两个较简单场景，后三个场景全部失败，Dev TGC 仍只有 8.8%，更符合局部轨迹记忆而非通用工具策略学习。Full-SFT epoch2/5 在训练内均为 0/15，排除了“仅仅是 Dev 过拟合”的解释：全参训练没有形成端到端可用策略，并伴随大量 50 步循环、空内容或少量动作后错误结束。epoch5 的断言率从 epoch2 的 17.9% 恢复到 29.8%，但仍未转化为任何 TGC，表明模型学到的是局部动作先验，而不是目标验证与状态闭环。

## 为什么成功轨迹没有带来稳定提升

1. **监督目标偏向模仿 token，而非验证环境状态。** 训练可提高局部 API/代码序列的复现率，却没有直接优化最终 evaluator；因此经常出现 5/6、7/8 断言后仍失败，或错误 success 声明。
2. **单一成功轨迹缺少反事实与纠错。** 数据只展示一条成功路径，未教模型遇到 401、参数错误、空结果或状态偏移后如何恢复；复杂场景容易重复调用直到 50 步。
3. **跨应用依赖没有被显式建模。** 简单 Spotify/phone 类任务提升更明显，file_system 与多应用组合仍差，说明模型更容易记住调用表面形式，而没有稳定学习认证、对象 ID、前置状态与后置验证之间的关系。
4. **Full-SFT 更新过强。** Full2/5 的 Train TGC 都为 0，且低于 Base；这与灾难性遗忘或学习率/更新量过大一致。epoch5 仅恢复部分断言，不支持“再多训几轮就会收敛”的判断。
5. **接口不是主要解释。** 四组先分别通过 smoke；Base 使用原 Dev 的 `deepseek_r1`，训练模型使用 aligned Dev 的无 reasoning parser 路径。正式任务中官方报告均写盘，故差异主要来自模型行为而非字段消费错误。

## 下一步建议

优先做小规模可证伪实验，而不是立即扩大到全部 Train：对同一 scenario 构造“成功轨迹 + 失败恢复轨迹 + 最终状态验证”三类样本；SFT 时降低全参学习率或采用 LoRA，并加入只训练 action/observation 后关键 token 的 loss mask；推理时增加 evaluator-like 自检（完成前核对目标状态）与重复错误熔断。若 LoRA 在这 15 题上的 4/15 能通过上述数据改造提高，同时 Dev 不下降，再扩展到完整 Train 并考虑 DPO/RL。

## 限制

样本仅 15 题、每模型单个确定性 seed，且任务来自训练集；结果适合定位是否学到训练轨迹，不足以作为论文最终结论或泛化性能估计。场景是从含完整三个变体的 SFT67∩Train90 中固定选择，复杂度与应用覆盖较广，但不是随机抽样。
