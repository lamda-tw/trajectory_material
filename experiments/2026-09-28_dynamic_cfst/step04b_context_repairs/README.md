## 结论

你的理解是正确的：本步不是把“超上下文”本身标成恢复错误，而是回到第一次上下文拒绝之前，检查是否已经出现可替换的错误动作。实际证据显示，8题中只有2题像“报错后继续无效操作”的恢复问题；另外6题主要是把完整列表或无关状态写进对话，属于状态读取与上下文控制问题。恢复错误在当前来源轨迹里确实很少。

## 为什么不能进入训练

第4A步结束时为状态8、参数7、恢复1。本步新增4条全部是状态类，最终为状态12、参数7、恢复1。参数仍差1条，恢复仍差7条；来源60题的23个未超限失败和8个上下文失败都已经耗尽。继续在这8题上换位置或重采教师，会改变预先冻结的选择过程，也不能解决恢复样本稀少的问题。

因此训练门槛冻结为未通过。下一步需要另行设计新的来源轨迹采集方案，重点产生“环境已经返回错误，但学生随后重复、误判或放弃”的真实恢复失败；不能从检查30题或Dev57取教师答案补数。
