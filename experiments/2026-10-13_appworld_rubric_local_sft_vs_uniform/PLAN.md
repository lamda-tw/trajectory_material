# 用现有 v5 评分选择原始步骤：LoRA SFT 与均匀抽样对照

本实验只回答：在同一原始 Qwen3-8B、同样训练题目和监督 token 预算下，rubric 选择的局部响应是否比均匀抽样更能提升 DEV57 官方成功率。用户禁止用 Codex 替换失败动作；本实验不请求新动作、不调用外部 judge、不构造跨状态偏好对，只使用已有 540 条轨迹和冻结 v5 标签。

**策略决定：先做局部 SFT。** 错误标签能说明某个已有动作不宜模仿，却没有给出同一状态下该做什么。当前没有足够的同状态 chosen/rejected 配对，不能将不同轨迹的同一步号直接拼成 DPO；固定离线数据做 GRPO/PPO 又需要额外定义 reward、组内优势及处理策略偏移。第一轮将这些因素固定在范围外，直接检验选择数据的作用。失败步可以出现在真实历史中，loss 只作用于选中的当前响应，不把错误前缀重新作为目标。

**为什么不数 PASS 或给八维拍权重。** 适用维度多的写入/恢复步骤天然可能有更多 P，查询步骤有很多 N；P 的数量不等于正确程度或学习价值。正确计算不能抵消错误修改对象，一个明确业务 F 不能被多个文档/执行 P 冲淡。N 不计好坏；U 也不是失败，只是本轮正向监督暂时不选择。第一轮使用容易解释的二元准入条件，而不是任意的连续权重。

全量评分中，R1=P 且八维只含 P/N 有 1,592 步，但 R5=P 只有 4 步，R7=P 为 0；若把 R8 完全作为硬门槛，会几乎排除所有业务修改。R8 混合了未先查文档、代码块、环境与授权约束：本轮用确定的结构检查排除多代码块和截断生成，同时保留 R8 标签作诊断，不让“先前未查完整文档”独自决定一个已有局部动作的监督资格。R8=F 不等于应当无条件忽略协议；这是为了测试业务筛选而预先写明的取舍。

| 条件 | 本轮用途 |
| --- | --- |
| 实际有代码，观察没有执行异常，恰好一个闭合 Python 块，生成未截断，长度≤32000 | 两组共同的机械准入条件；避免把语法/多代码块错误特意塞给均匀基线 |
| 实际代码包含 complete_task | 两组均不作为目标，避免把有噪声的结束判断当正确动作；基本结束能力由原始模型保留 |
| 完全相同的 prompt_ids + response_ids | 两组共用去重规则，保留来源；当前数据无重复命中 |
| R1=P | rubric 组再确认执行维度 |
| R2/R3/R4/R5/R6 均属于 P 或 N | rubric 组的语义门槛；任一 F 或 U 则不作为正向目标 |
| R7=N | rubric 组不模仿声称完成等交付文本；均匀组不查看此标签，因此仍可能抽到未调用 complete_task 却声称完成的文本 |
| R8 | 保存并报告，不计分、不设固定权重；部分协议错误因此仍可能被模仿，这是明确限制 |
| 官方 train 成败 | 不参与选择、配额或训练；成功、失败轨迹同标准 |

共同候选池 5,234 步，rubric 候选池 2,580 步，均覆盖 train90。rubric 候选主要仍是有效读取、状态解释和恢复，并不意味着它们已经被证明“因果重要”或“最值得学习”。R4=P 有 88 步、R5=P 有 22 步，复杂业务的正确行为供给有限；无新动作的方案能够强化已有行为，不能凭空补充数据里从未出现过的正确策略。

**配对预算。** 两组均监督 196,608 个原始 response tokens（48×4096），48 次 optimizer update。按 rubric 候选的每题 response token 总量用最大余数法分配固定配额；均匀组使用完全相同的每题配额，在共同池内按固定随机排列无放回取样。这是“题目和 token 配额匹配的均匀抽样”基线，不是假称全体 step 全局同概率、又不控制题目比例的另一种基线。

每题达到配额时，只对最后一个原始响应的必要前缀计算 loss，余下 token 不监督；更新边界处可将同一响应的目标 token 分成连续区间，各 token 最多监督一次。没有重写、替换或伪造任何字符/token，没有把裁剪后的响应当成完整动作重新执行。保存准确 loss span，前文全部提供但无 loss。这样可以严格控制各题和总监督 token，不能声称两组输入计算量也相同：rubric 组前缀较短，预计处理约 1,400.7 万 input tokens，均匀组约 1,701.3 万。

最终 rubric 组涉及 2,440 个 step，均匀组 2,239 个，交集 1,173 个。两组 step 数不同是 response 长度不同所致，不重复采样补齐；学习预算以监督 token 和更新次数为准。共同池里的一个 R1=F 是此前已确认的 judge 误判（执行实际正常），均匀组可以抽到它；不通过改写原始标签人为修正实验结果。

**训练。** 从原始 `/root/autodl-tmp/models/Qwen3-8B` 各初始化一个全新、相同 seed 的 LoRA；不用旧 SFT/GRPO adapter。rank16、alpha32、dropout0，q/k/v/o/gate/up/down 投影；bf16、SDPA、梯度检查点。AdamW，lr=5e-5，4 次 warmup，随后 cosine 降至5e-6，weight_decay=0，clip_norm=1。每次更新对4,096个目标token的 CE 求平均；无负向loss、无rubric权重、无KL/旧logprob比率。每组只训练冻结计划一次，保存最终adapter；不根据DEV挑中途checkpoint。

**验证。** 两组训练后各跑完整官方 DEV57；另以原始模型同协议新跑57题。temperature0、seed100、enable_thinking=false、50步、32000窗口、每步3000生成token；上下文溢出终止，不裁掉历史。三组使用相同任务顺序、提示、解析器、工具环境和官方评测器，不用DEV rubric分数选模型。历史DEV部分使用不同thinking协议，不直接拿历史成绩充当本实验基线。主要比较rubric与uniform的逐题配对TGC差异，同时报告相对base的新增成功/退化、SGC/测试通过率描述、成本、终止类型和精确McNemar检验；只有57题和一个训练seed，结论是初步对照，不能保证统计显著或普遍有效。

**参考与区别。** [CSO §3.2–3.3](https://arxiv.org/html/2602.03412v1#S3.SS2) 不只使用PRM分数，还生成专家替代动作并以学生续跑验证，再构造局部DPO。按用户约束，本轮仅借鉴局部选择粒度，不使用它的替代动作和偏好构建，因此不声称复现CSO。[DRACO §3.3](https://arxiv.org/html/2609.04094v1#S3.SS3) 将轨迹相对优势按 rubric 归因分配到step：轨迹优势的正负决定强化/抑制方向，步骤质量决定分配量。它的PASS比例不是独立的“学习价值”，也不是直接从现有逐步标签得到的SFT权重；本轮不把该公式照搬成八维PASS总和。

**与新版 prompt 的关系。** 本轮训练只消费v5评分。v5全量实验没有修改prompt；先前报告只有改进建议。可另存v6供将来新数据使用，明确未经新评分实测，绝不拿它覆盖或重新解释现有v5分项。训练期间不调用Codex。

所有选择、配额、token来源、配置和执行日志保存于本实验目录；`data/DATA_MANIFEST.json` 在训练前冻结。DEV结果不得反向改变本轮门槛、预算或报告取舍。
