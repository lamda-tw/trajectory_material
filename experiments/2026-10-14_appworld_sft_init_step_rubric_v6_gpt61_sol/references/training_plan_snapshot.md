# AppWorld：先评分，再进行局部 SFT + 在线结果 RL

日期：2026-10-13（北京时间）。状态：**待审查；本次只修订计划，尚未启动评分或训练。**

## 1. 目标与实验范围

本次只训练一个模型，回答：

1. 这套“离线步骤评分 → 选出局部监督 → 局部 SFT 与在线结果 RL 联合训练”的流程，能否完整、正确地运行？
2. 最终模型相对于训练前的 SFT 模型，在相同协议下的 DEV57 官方成功率是否提升？

纯 RL 消融留到本次完成后再考虑。本次不设置均匀抽样对照，不引入新的教师替代动作。

**数据边界：评分对象、局部 SFT 来源和模型起点均围绕用户指定的 SFT 模型。不得使用原始 Qwen 模型那批轨迹的旧标签、选样清单、样本数量或监督 token 预算。**

流程如下：

~~~text
已有的 epoch5 SFT 模型及其采集的 540 条轨迹
                 ↓
    对这 540 条完整轨迹做本次逐步 rubric 评分
                 ↓
   分析标签、制定筛选规则、确定实际局部 SFT 数据
                 ↓
        冻结本次训练配置与预算
                 ↓
  从同一个 epoch5 SFT checkpoint 开始联合训练
       ├─ 固定的已评分步骤 → 局部 SFT
       └─ 当前模型新采样 → 官方成败奖励 → RL
                 ↓
          训练后与训练前比较 DEV57
~~~

评分成本的边界：**先为现有 540 条轨迹做一次离线评分；之后在线 RL 新产生的轨迹仅做官方成败检查，无需继续请求 Codex 逐步评分。** 本次有初始评分成本，不能写成“整个实验新增外部调用为零”。

## 3. 第二步：根据本次标签确定局部 SFT 数据

这一阶段要形成新的 selection_policy 和 data_manifest，而不是套用上一批数据的筛选清单。

先统计本次数据：

- 各维度 P/F/U/N 的分布，以及不同任务、动作类型的覆盖。
- 查询取证、业务计算、实际修改、错误恢复、结束交付分别有多少可靠候选。
- 成功和失败轨迹里可用步骤的数量与证据。
- 生成截断、多代码块、执行异常、过长上下文和重复动作的情况。
- 严格筛选后是否只剩容易的文档读取，而缺少真正完成任务需要的动作。

然后制定本次具体筛选规则：

1. 正向监督只选择有证据支持其动作适当的步骤；明确错误步骤不作为模仿目标。U 不自动视为失败，N 不当作额外 PASS。
2. 不按 PASS 总数排序，也不提前给 R1—R8 拍固定权重。
3. 成功轨迹中的步骤不自动全选，失败轨迹中的正确步骤也不自动丢弃。
4. 不预先照搬“排除全部收尾动作”或“整体忽略某个维度”的旧规则。根据本批评分检查具体错误及适用性，再明确哪些标签组合可以训练。
5. 结束步骤必须区分正确完成与诚实报告失败；R7=P 本身不保证动作是在完成任务。
6. 若一步包含正确和错误的多项操作，而现有标签无法可靠定位到 token，不自行伪造细粒度监督边界。
7. 全部使用原始动作，不生成替代动作。选中后保留完整目标响应；机械过滤和去重原因逐项保存。

筛选规则在观察本次训练数据后制定，在正式训练及查看 DEV 训练后成绩之前冻结。记录每个入选和排除步骤的依据，报告结果偏向哪些动作类型。

将最终选中的不同步骤数记为 N，完整目标 token 总数记为 S。这两个值**待本次评分和筛选完成后计算**。同时报告覆盖题目数、成功/失败来源比例、动作类型分布、长度分布与去重数量。

SFT 样本：

~~~text
输入：题目 + 该动作之前的完整历史
目标：选中的原始 assistant 动作响应
loss：仅计算当前目标响应的 token
~~~

输入可保留此前的错误动作和执行反馈，但不监督历史本身。本动作执行后的观察、最终答案、官方结果和 rubric 标签不能提前加到动作的输入条件中。

**本步产物：** selection_policy.md、selected_steps.jsonl、data_manifest.json、目标 token 与 loss mask 校验、N 和 S 的实际统计。

## 4. 第三步：把三个“轮数”分别确定

“每批 RL epoch=1”不表示整个实验只训练一轮。必须分别配置和记录：

| 名称 | 含义 | 本次建议 |
| --- | --- | --- |
| 在线采样轮数 | 当前模型遍历 train90、采样并更新的次数 | 拟定 5 轮；每批使用更新后的策略重新采样 |
| 局部 SFT epoch | 固定局部监督数据被完整学习的次数 | 拟定 5 遍；总监督量为 5S |
| 每批 RL 更新遍数 | 同一批已经采样的 RL 数据被重复优化几遍 | 初始建议 1 遍，工程检查后冻结 |

### 4.1 为什么不把所有 epoch 都直接设为 5

SFT 是对固定监督目标重复学习；一遍是否足够需要检查，所以本次提议完整学习 5 遍。

在线 RL 会在模型更新后不断生成新轨迹。每批只更新一遍、然后采下一批，也会在整个实验中产生很多次更新，不是只执行一次 optimizer.step。

如果同一批 RL 数据重复更新 5 遍，第二遍之后模型已经偏离采样时的行为策略。多遍更新可以提高样本利用率，但需要核对概率比、KL、clip fraction 和更新幅度；不能因为原来的 SFT 用过 5 个 epoch，就自动把每批 RL 也设为 5。

因此，当前建议是“5 轮在线采样 + 5 遍局部 SFT”，每批 RL 先按 1 遍设计。是否需要增加每批 RL 的更新遍数，应根据工程试跑与训练信号判断，不预设 1 遍一定充分，也不预设更多遍一定更好。

### 4.2 不再预填与本次数据无关的预算

正式配置在本次评分、筛选和工程测量后补齐：

| 参数 | 确定依据 |
| --- | --- |
| N、S | 本批评分后真正选出的步骤和目标 token |
| 每题新采样数 G | 奖励差异、轨迹成本与资源；旧采样每题 6 条仅是参考 |
| 每批题目数 B | 实际轨迹长度、显存和梯度累积开销 |
| 每批 RL 更新遍数 K | 初始建议 1，结合策略偏移检查冻结 |
| 学习率、KL 系数、SFT 混合系数 | 本模型联合训练的数值与梯度检查 |
| attention、微批大小和并发 | 当前资源和实现验证 |
| 随机种子与任务顺序 | 本实验独立记录，保证可复现 |

若在线轮数为 E=5，每轮每题采样 G 条，则正式训练采样数为 E×90×G。若每批 B 题、每次完整批次遍历后更新一次、每批重复 K 遍，则更新数为 E×ceil(90/B)×K；尾批按实际题数归一化。具体执行器若采用其他优化粒度，须按实现重新计算并记录，不能套用该式。

局部 SFT 总监督量拟为 5S。根据最终更新数编排消费计划，使五遍目标 token 完整覆盖；微批或 loss span 拆分只用于计算，不丢弃原始响应内容，不制造新动作。

**本步产物：** 写清全部实际数值的 training_config.json、预算表和 SFT 消费计划。正式训练开始前必须具体化；不能带着未填配置启动。

## 7. 第六步：执行多轮局部 SFT + 在线结果 RL

### 7.1 一批数据如何共同更新模型

1. 当前模型在 B 道 train 题上分别独立采样 G 条完整轨迹；这批采样完成前不更新参数。
2. AppWorld 官方终态检查给出奖励。完整成功为 1，模型造成的失败为 0；基础设施故障修复或重试，不作为失败奖励。
3. 在同一道题的 G 条轨迹内计算组内相对优势。
4. 使用新轨迹的生成 token 计算策略 loss，以及相对于初始 SFT reference 的 KL。
5. 从本次评分后冻结的局部 SFT 数据中读取计划样本，计算当前响应的 CE。
6. 两部分梯度合并，按冻结配置更新同一个 LoRA；若 K>1，保持该批行为策略概率固定并正确记录各遍更新。
7. 保存恢复状态、刷新推理服务上的实际模型，进入下一批重新采样。
8. 按计划完成 5 轮训练题遍历及 5 遍局部 SFT 数据学习。

训练目标写为：

L_total = L_GRPO + beta × L_KL + lambda × L_local_SFT。

beta、lambda 和学习率在工程检查后填写实际数值。本次不将 rubric 标签直接变成新轨迹的 RL reward，不给各 rubric 维度预设数值权重。

终态奖励的组内优势为：

A_i = (R_i − mean(R)) / (std(R) + epsilon)。

标准差约定与 epsilon 写入正式配置。全等组优势显式置零。工具观察和 prompt 没有 RL loss；历史不作为局部 SFT 的目标。所有 loss 的分母、生成 token mask 与梯度累积规则必须与配置一致。

reference 为冻结初始模型；行为策略为每批采样时的模型，两者分开保存和检查。没有步骤级 RL 奖励时，不把轨迹优势说成已精确定位了错误动作。

### 7.2 新轨迹的评分与计时边界

训练期间新轨迹只运行官方成败检查，不再调用 Codex 做逐步评分。初始 540 条评分的标签作为固定监督来源，训练期不重写它们。

分别统计：

- 初始 540 条的外部评分调用、重试、token 和耗时。
- 数据分析、筛选与构造耗时。
- 新轨迹采样与环境执行、官方检查耗时。
- 模型训练、权重同步、保存和恢复耗时。
- DEV 评测、案例分析与报告耗时。

### 7.3 每轮检查与保存

每轮记录成功率、全失败/混合/全成功组分布、动作长度和终止类型；记录 RL loss、SFT CE、KL、梯度范数、概率比和 clip fraction。全等组不反复重采样直到成功，也不为制造优势临时改奖励。

保存每轮 checkpoint 与必要的 optimizer/RNG/数据游标。记录实际消耗的监督 token、实际采样数和更新数。出现 NaN、概率错位、错误权重加载或不可确认的断点时，先修复工程问题，再从可信状态恢复。

**本步产物：** 训练日志、完整新轨迹索引、每轮模型、预算与成本账本。

## 8. 第七步：验证最终性能并撰写报告

拟在第 1、3、5 轮分别完整评测 DEV57，观察学习过程；以第 5 轮相对于初始模型的结果作为主要比较，不挑中途最高分代替最终结果。

报告必须包含：

1. 流程是否完成：初始评分覆盖率、实际选样数量、联合训练和保存重载是否通过、是否达到计划训练量。
2. 训练前后 DEV57 成功数、成功率、差值，以及新增成功与退化的具体题目。
3. 训练曲线与第 1/3/5 轮评测，判断是否仍在改善、过拟合或退化。
4. 代表轨迹的实际变化，区分局部动作改善、任务完成改善与偶然成功。
5. 全部阶段成本，单列初始外部评分和后续在线训练。
6. 尚不能回答的问题：一次实验的提升不能单独证明局部 SFT 的贡献，五轮也不自动代表充分收敛。

若最终成绩没有提高，照实报告，不能将“能跑通”写成“有效提升”。若训练尚未完成，报告实际进度，不将部分结果写为完整实验。
