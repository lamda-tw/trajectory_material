# 用 rubric 反馈纠正 FAIL 步骤：阶段 A/B/C 执行计划

日期：2026-10-21。版本：v1。状态：**已完成原始数据核对与固定抽样；尚未重放环境、调用 Qwen/Codex 或训练。**

本计划先回答：同一个错误发生前的状态，Qwen3-8B 在看到具体 Codex 反馈后，能否比自己重新尝试更可靠地采取有效动作？若答案成立，再验证反馈条件下的模型分布能否作为 SDPO 教师，最后检验在线训练是否提高 AppWorld 任务完成率。阶段 A 是诊断，不是训练；它成功也不直接证明阶段 C 会成功。

## 1. 与已有实验的关系

数据来源为 `experiments/2026-10-16_appworld_rubric_selection_ablation`：原始 Qwen3-8B 在 train90 上每题 6 条轨迹，共 540 条、11,254 个步骤。沿用原始 `appworld-step-v6` 的 R1–R8 定义，不能悄悄切换为最近同状态实验使用的 v7。

| 原始步骤类别 | 数量 | 对本计划的意义 |
|---|---:|---|
| F ≥ 1 | 9,539 | 阶段 A 的错误状态候选池 |
| F = 0，P ≥ 3 | 1,710 | 原 ZeroFail3 的正样本定义；其中 46 个含 U |
| F = 0，P = 2 | 5 | 都是 `PUUUNNNP`；保留上下文，不作为负例 |
| F = 0，P = 1 或 0 | 0 | 本批数据里不存在，不必凭空设计大量此类样本 |

干净对照从 F=0、P≥3、U=0 的 1,664 个步骤中抽取。这个更严格的条件只用于阶段 A 对照；阶段 B 的 SFT 默认仍使用原 ZeroFail3 定义，避免同时改变正样本规则。

现有 FAIL 中，8,951 个含 R6 或 R8。若均匀抽步骤，结果容易主要反映恢复与协议行为；所以阶段 A 按问题类型平衡抽样。它估计的是**四类错误的平衡诊断表现**，不能直接解释成原始数据的总体纠错率，更不能解释成 AppWorld 任务成功率。

可复用 `experiments/2026-10-20_appworld_zerofail3_same_state_mechanism` 的状态重放、完整 SQLite 快照、公开证据整理与盲评方式；不复用其中的 dev57 状态、候选动作或 v7 标签作为本次训练集诊断样本。旧脚本含固定实验路径，后续必须适配新目录，不能直接运行旧 runner。

## 2. 阶段 A 的固定抽样

### 2.1 已生成的清单

抽样脚本为 [prepare_plan.py](prepare_plan.py)，种子为 `20261021:rubric_sdpo_A:v1`。正式清单 [states_selected.csv](states_selected.csv) 已生成，调试清单为 [calibration_states.csv](calibration_states.csv)，审计为 [selection_audit.json](selection_audit.json)。

四类按以下**先后顺序互斥划分**，保留每个步骤完整的原始八维标签，不把其他违规删除：

| 层 | 分配规则 | 候选数 | 正式抽样 | 调试抽样 |
|---|---|---:|---:|---:|
| semantic：证据、事实、决策、效果或交付 | 任一 R2/R3/R4/R5/R7 为 F | 4,396 | 25 | 2 |
| execution：执行问题 | 不属于上一层，R1 为 F | 2,575 | 25 | 2 |
| recovery：恢复问题 | 不属于前两层，R6 为 F | 1,070 | 25 | 2 |
| protocol_only：纯协议问题 | 不属于前三层，仅 R8 为 F | 1,498 | 25 | 2 |
| good_control：干净对照 | F=0，P≥3，U=0 | 1,664 | 30 | 0 |

100 个正式 FAIL 状态覆盖 **90 道题、30 个题目家族、100 条不同轨迹**；每题最多 2 个，每个家族最多 4 个。30 个干净对照每家族 1 个。8 个调试状态来自另外 8 条轨迹。

全部 138 个状态的原始 prompt token 序列互不重复，来源轨迹也互不重复。这消除了同轨迹和完全相同模型输入的重复，**不宣称隐藏环境状态都不等价，也不把同家族状态当成完全独立样本**。

FAIL 正式样本的历史长度：≤4,096 tokens 为 33 个，4,097–8,192 为 35 个，>8,192 为 32 个。脚本先满足问题类型配额，优先覆盖未抽中的题目/家族，再平衡各层历史长度，最后按固定哈希排序；不是抽最短、最容易修的步骤。没有使用官方成功标签、后续轨迹结果或新模型输出选样。

### 2.2 调试与正式集的边界

先用 8 个调试状态检查重放、反馈格式、提示词渲染、动作执行和盲评。可以据此修复程序和歧义，但每次改动都记录版本。正式 130 个状态在调试结束前不生成候选回答；正式结果不能用来反复改 prompt 后只报告最后一次。

正式集不因“太难”“反馈效果差”“未纠错”而换样。旧标签无法由局部证据支持、反馈不合格、上下文过长、状态重放失败等均保留原始条目与原因，并报告覆盖率。若覆盖不足，先报告协议问题；重新扩样或改协议属于新版本实验。

## 3. 阶段 A 的实验条件与预算

使用**产生原始轨迹的 Qwen3-8B 基础 checkpoint**，不加载 ZeroFail3 或其他已训练 adapter。执行前从原 rollout 配置解析实际模型路径，固定模型 revision/文件摘要、tokenizer、chat template、推理后端版本和原始 agent prompt。只写“Qwen3-8B”不足以确定模型。

对每个 FAIL 状态运行以下四种条件；每种独立采样 2 次：

| 条件 | 给模型的输入 | 回答的问题 |
|---|---|---|
| C0：无反馈重试 | 原始动作前历史 h | 原错误是否仅靠重新采样就能修复？ |
| C1：仅标签 | h + 经核实的 FAIL 规则编号及名称 | 知道错在哪类是否已足够？ |
| C2：具体反馈 | h + 同一规则列表 + 具体诊断与修正约束 | 具体反馈是否提供额外帮助？这是主处理条件。 |
| C3：反馈加原回答 | C2 + 完整原始 assistant 回答的引用 | 完整错误回答是帮助定位，还是造成错误锚定？ |

C1/C2/C3 的规则列表相同；C2/C3 的反馈逐字相同。C2 可以引用必要的短错误表达式，但不能把完整失败代码或完整答案藏在反馈里。C3 引用的原回答包括模型原始文本，不能只截出看起来最容易修的片段。

30 个干净对照只运行 C0 与 C2，各 2 次；C2 使用固定中性消息，不编造错误，也不提供原回答。它检查额外诊断上下文是否破坏本来有合理下一步的状态，不要求模型逐字复现原动作。

正式生成上限：`100 × 4 × 2 + 30 × 2 × 2 = 920` 次。调试生成：`8 × 4 × 1 = 32` 次。该预算是**下一动作数**，不是完整轨迹数；阶段 A 不安排完整续跑或训练。外部反馈最多 108 个 FAIL 状态各一份；每份复用于所有条件与重复采样。正式候选最多 920 条分别盲评；调试盲评最多 32 条，格式修复和人工复核额外计数。

生成参数沿用原采集习惯：temperature=1、top_p=1、top_k=-1、repetition_penalty=1、enable_thinking=false，最大上下文 32,000、最大新输出 3,000 tokens。种子由“实验种子、状态 ID、条件、重复序号”稳定派生，各条件使用独立随机流；两次采样都保留，不能选最好的一次当主结果。种子相同也不保证 GPU 推理逐字确定，必须保存真实输出。

不截断历史。先计算 C0/C1/C2 的 prompt 长度，为三者设相同输出预算 `min(3000, 32000 - max_prompt_len)`；不足 128 tokens 时该状态记为主比较上下文不可用。C3 只有在容纳完整原回答、且保留同一输出预算时才运行，否则仅 C3 缺失，不能让次要对照决定 C2−C0 的样本组成。对干净对照按 C0/C2 同样处理。逐条记录实际预算、终止原因及长度。

## 4. 反馈 prompt 与证据边界

模板：[feedback_v1.txt](prompts/feedback_v1.txt)；模型重提示构造：[teacher_reprompt_v1.txt](prompts/teacher_reprompt_v1.txt)。

反馈生成器使用原实验的 Codex 评分配置作为起点（现有配置记录 GPT-6.1-sol/high、tools=false），执行前记录实际服务返回的模型标识。输入只包括：任务与原 agent 规则、动作前完整公开历史、当时可见的 API 文档、原动作、该动作的即时执行 observation，以及待核实的原标签和短理由。R1–R8 定义从冻结 v6 文件抽取；不直接套用其整轨迹输出壳。

反馈分成两层输出：

1. **审计字段**：逐一确认原 F 是否由当前局部证据支持；引用依据；列出不支持或矛盾的历史判断。这些元数据用于审计，不全部发给 Qwen。
2. **给 Qwen 的短反馈**：发生了什么具体问题，以及下一动作应检查/满足什么约束；最多 3 条、Qwen tokenizer 下不超过 256 tokens。覆盖所有已确认的 F；无法在预算内可靠覆盖则标记不可用，不能截断后假装完整。

示意反馈：

> The attempted action used an API without a complete specification visible in the prefix. Retrieve the missing specification before using that API. A successful earlier call does not satisfy this requirement.

这只是格式示例，只有实际证据成立时才可使用。反馈不要求 Codex 给出完整正确代码，也不允许猜测工具签名、编造任务值或使用官方答案。它可以利用原动作的即时报错解释问题，但必须说明这是**另一次尝试的诊断证据**：当前环境已恢复至原动作之前，原动作刚创建的变量、读取结果或写入效果都不能当作当前已有状态。

尤其注意：旧 v6 标签来自整条轨迹审阅，部分 F 可能需要后续证据才能确认。阶段 A 不能把这些后见信息悄悄注入教师。保持旧标签不变，同时生成本实验独立的 `confirmed_fail_rules`；至少一个原 F 被局部证据确认，且反馈合格，才进入“可用反馈”分析集。此集合必须在任何正式候选生成前冻结。

外部 Codex 输入沿用已有公开证据与凭据脱敏管道，保持凭据相等关系；不能只按字段名脱敏而漏掉自由文本密码。隐藏测试、官方 evaluator 答案、私有快照和最终成功标签不进入反馈或动作评审。模型实际动作上下文保持其原本获准使用的信息，不用脱敏后的外部评审文本替换真实执行上下文。

## 5. 同状态重放：必须在原错误发生之前分叉

1. 校验清单中的源文件、原 prompt IDs 和原 response IDs 哈希。用原 initial_messages、先前的 `history_assistant_text` 和 observations 重建结构化历史；C0 序列化 token IDs 必须与保存的 `prompt_ids` 完全一致。
2. 从任务初始状态按顺序重放**所有实际执行的先前代码**，包括最终报错的代码。报错前可能已产生写入，不能略过报错步骤或假定自动回滚。
3. 在目标步骤执行前保存完整可恢复状态：Python 变量与必要执行上下文、数据库及相关文件、时间/RNG 等已有框架可恢复的状态。SQLite 使用已有完整备份方法，保留 FTS/shadow tables；不能只导出普通表。
4. 对调试 8 个状态分别独立重建两次，核对状态指纹、前缀 observation、API 请求/响应与模型输入。对正式状态也验证历史和快照恢复一致性。已有编码器不支持的对象，例如 `datetime.timedelta`，需要明确支持并验证，否则记基础设施不可用；不能忽略差异以通过检查。
5. 每个条件、每次采样都从该**同一动作前快照的新副本**执行。原失败动作若为复核而重跑，也用单独副本；其部分写入不能污染修复动作的起点。
6. 候选代码继续使用原动作解析器与协议。空输出、无可执行代码、错误格式、模型生成的执行异常或超时计为模型结果；状态加载失败、进程崩溃等独立标为基础设施故障。仅基础设施故障允许同一缓存动作重放一次，不能重新生成一个更好的答案。

模板渲染必须从结构化历史加入反馈 user 消息后重新应用 chat template；不能把字符串直接接到已打开的 assistant generation marker 后。完整原回答只在 C3 的引用数据里出现，不能伪装成已经执行过的历史消息。

保存生成文本、实际执行 code、即时 observation、执行前后指纹、请求 trace、种子、输入/输出 token 数及所有版本摘要。失败也保存，不能只存成功纠错案例。

## 6. 评估标准：纠错必须同时产生有效下一步

### 6.1 独立盲评

模板为 [action_judge_v1.txt](prompts/action_judge_v1.txt)。独立评审调用只看到原公开历史、匿名候选回答、实际执行代码与即时 observation，看不到原失败动作、该条件反馈、模型名、条件名或原轨迹最终结果。评审返回八维标签、每维依据，以及进展类型。先独立判断动作，再由程序与原已确认 F 集合比对，避免评审照着反馈宣称“已修复”。

这里使用 **v6 规则定义 + 单动作证据窗口的新评审壳**，版本记为 `appworld-local-repair-v1`；不把其局部标签伪称为原整轨迹 v6 评分。U 不能当 F，也不能自动当 P。JSON/标签/证据结构不合法时只允许一次格式修复；保留原返回和修复记录。合法但不利的判断不重抽评审。

调试 8 个状态全部人工复核反馈与候选评审。正式反馈只做预先定义的格式/证据引用/覆盖检查，并在生成候选前统一冻结；不能看纠错结果再重写。正式输出另固定抽 20 个状态（每个 FAIL 层 4 个、干净对照 4 个，固定哈希选择）进行隐藏条件的人工复核，查看全部候选。审阅者先独立打标再看自动判定。人工结果与自动结果分开报告；若暴露系统性评审问题，应统一修正协议并重评全部候选，不能只改有利条目。

### 6.2 主指标：有效纠错率 ER

对状态 s，设 `D_s` 为反馈准备阶段冻结的、经局部证据确认的原 FAIL 维度集合。一次候选的 ER=1 当且仅当：

- 当前动作 R1=P，实际可正常执行；
- 所有八维都没有 F；
- `D_s` 内每一维均为 P 或有充分适用性解释的 N，不能为 U；
- 有明确的有效进展：获得当前确实缺失且有用的证据，执行有依据的任务操作，或有充分证据地完成交付。

不计进展的情形包括：空动作、无必要地反复查同一文档、无依据地宣布完成、诚实认输但任务未完成。必要的首次文档查询可以计进展；它证明局部纠错能力，并不证明任务最终会完成。候选其他维度含 U 时不自动失败，但单列 U 比例，并补报“ER 且所有维度 U=0”的更严格结果。

主比较：**C2−C0 的 ER 差值**。每个状态先平均两次采样，再计算各层的状态均值，最后四层等权平均。原动作因本来就被挑选为 FAIL，不能用“C2 比原动作好”代替这个重新采样对照。

### 6.3 次指标与分母

| 指标 | 用途 |
|---|---|
| 原 F 清除率 | `D_s` 全部变 P/N；允许同时出现新 F，用于区分“修了旧错却引入新错” |
| 新出现 F 的维度比例 | 相对已确认原 F 集合，候选在其他维度出现 F；另列已知错误写入和虚假完成。它是操作性比较，不证明原 U/未核实维度此前确实正确。下文“新违规率”指此指标。 |
| 有效进展率、无效重复率 | 排除“少做事所以少犯错” |
| C2−C1 | 具体反馈是否优于规则提醒；是支持性对照，不另挑最有利指标 |
| C3−C2 | 完整原回答的增益/锚定风险；仅报告共同可运行状态与覆盖率 |
| 干净对照的 C2−C0 | 固定中性诊断上下文是否降低无 F 且有效进展的比例 |
| token/耗时、超长、格式失败与执行异常 | 判断后续教师与环境开销是否可承受 |

主效果在**候选生成前确定的可用反馈与可恢复状态集合**上计算，每一对条件使用同一批状态；报告实际 n 和每类排除原因。另以原 100 个 FAIL 状态为固定分母，报告“可提供反馈并成功修复”的覆盖调整后产出，未覆盖状态贡献 0；这不是对未运行 C0 的补造结果，不能据此计算虚假的全 100 状态因果差值。报告未经覆盖调整的结果与该产出两者，避免只展示容易提供反馈的状态。

置信区间使用题目家族聚类 bootstrap（30 个家族为抽样单元，10,000 次，seed=20261021），保留家族内所有状态和条件配对，每次重算四层等权差值；若某次缺失某层则重抽并记录次数。两次采样不是两个独立任务。小规模诊断以效应量与区间为主，次比较不据单次显著性作强结论。阶段 A 不报告任务 TGC 改善。

### 6.4 增加无梯度的教师分布检查

生成更好的修复动作，仍不等于在原错误 token 上的 SDPO 梯度可靠。正式样本另外用冻结 Qwen，对原始回答 `a` 做 teacher-forcing：分别在 h、C1、C2、可用时 C3 条件下计算同一 `a_j`、同一原回答前缀 `a_<j` 的 log-prob；**不反向传播，不更新模型**。

记录每步平均 log-prob 差、reverse KL、学生 top-100 概率质量、tail 质量，以及反馈中能精确对齐到原错误表达式的 token span 的差值。全回答平均概率降低不等于精确压制错误，因此将有可信错误 span 与无可信 span 分开报告；没有可定位 span 时不编造 token 标签。

若 C2 能生成更好动作，但在原错误前缀下仍强化明显错误 token，先检查反馈形式、原前缀锚定与 token 对齐。必要时把“重新采样学生动作后再蒸馏”列为后续协议变体，不能把这些分布异常忽略后直接声称原失败动作蒸馏已获验证。该项用于人工技术审查，不设置没有依据的统一 KL 数值阈值。

## 7. 阶段 A 的执行顺序与进入下一阶段的门槛

以下为执行顺序，不代表本轮已经执行：

1. **索引校验（已完成）**：生成两份清单、数据统计与哈希；`prepare_plan.py --check` 可复核。
2. **实现运行器（待做）**：新建独立实验目录，适配同状态恢复、公开 payload、反馈渲染、缓存生成、单动作执行、盲评和统计；不修改旧实验输出。
3. **调试 8 状态（待做）**：双重状态恢复、最多 32 个动作；人工核对反馈与评审；冻结代码、模型、模板和判分版本。
4. **冻结正式可用集（待做）**：检查 130 状态恢复与 token 预算；100 个 FAIL 生成/审计反馈。记录不可用项，不换样，不读取新候选效果来决定资格。
5. **生成并执行正式动作（待做）**：最多 920 次，各自恢复快照；输出缓存一次写入。
6. **盲评与分布检查（待做）**：生成评估表、聚类区间、固定人工复核表和 token 诊断。
7. **产出报告（待做）**：逐层结果、覆盖率、失败原因、至少各类成功/失败案例、下一阶段建议。不得只选成功案例。

建议事先固定的工程决策门槛如下；**这是小规模可行性标准，不是由功效分析得出的定律**：

- 绿色：主比较至少 80 个有效 FAIL 状态、每层至少 15 个；C2−C0 的 ER 提升 ≥10 个百分点且 95% 区间下界 >0；至少 3/4 层点估计非负；C2−C1 点估计 >0；新违规率增加和干净对照退化均不超过 5 个百分点；教师分布检查无未解释的明显反向信号。进入阶段 B 的小规模训练试验。
- 黄色：点估计改善但区间跨 0、仅某一层有效、覆盖不足，或具体反馈不优于标签。先说明不确定性，检查反馈/评审瓶颈；需要扩样或改 prompt 时建立新版本。不能把“统计不显著”当作证明无效。
- 红色：具体反馈没有正向点估计、明显增加错误写入/虚假完成，或同状态恢复不可信。先排查原因，不启动依赖该假设的训练。

干净对照只有 30 个状态，5 个百分点门槛只作风险提示，不能宣称统计上证明无害。即使绿色，阶段 B 仍检验训练是否稳定及效果能否迁移到不带反馈的学生。

## 8. 阶段 B：在线混合损失的小规模验证

### 8.1 要验证什么

检验 `ZeroFail3 SFT + FAIL 步骤反馈蒸馏` 是否能稳定优化，并开始改善**不接收反馈**的学生行为。保留在线 ZeroFail3 SFT 对照；现有离线 ZeroFail3 只能提供历史参考，因为样本分布、采集时机和更新次数不同。

阶段 A 的旧轨迹只用于诊断，不能把它们反复训练后称为 on-policy。阶段 B 从同一初始 Qwen3-8B checkpoint 为每个训练分支新建 LoRA，重新用当前学生采集 train90 轨迹。

### 8.2 每次采几条，何时更新

建议起点：每次随机取 **5 道不同题，每题 1 条轨迹**；同一批 5 条轨迹全部由同一学生版本产生。每轮打乱 90 题、无放回遍历，因此每轮 18 个更新机会。

在这 5 条完整轨迹评分完、生成所需反馈后，先确定 G/B 的数量与掩码，再以每个环境步骤为 microbatch 累积梯度；**所有选中步骤计算完才执行一次 optimizer.step**。随后更新教师 EMA、更新推理端 adapter，下一批使用新学生。不是“每个动作更新一次”，也不是先更新第一题再把其余旧轨迹当新策略数据。

先做每分支 2 轮：180 条轨迹、36 个更新机会、1 个训练种子；两个分支总计 360 条新轨迹。原始数据平均每条约 20.8 步，所以每批粗略约 104 步，其中约 16 个原 ZeroFail3 步骤、88 个 FAIL；这是历史预算估算，在线比例必须实测。相较单题采 4 条再更新，5 题各 1 条更适合先覆盖 90 题并降低同题相关性；不是普遍最优结论。

Codex 的 v6 评分仍可逐轨迹批量进行，但教师反馈对每个动作只使用其前缀和即时 observation。评分服务可以并发；学生参数在一批采集/评分/梯度计算期间保持不变。新模型不能在后台继续对已经排队的旧数据做多轮更新。

### 8.3 哪些步骤进入哪种损失

- `G = {F=0 且 P≥3}`：原回答做 SFT，包括原规则下带 U 的样本；额外记录 U 率，若要排除 U 必须作为单独消融。
- `B = {F≥1 且有局部依据充分的反馈且教师输入可容纳}`：原回答所在前缀做反馈条件自蒸馏；不对这些回答做正向 SFT。
- F=0、P<3：上下文保留，当前回答 loss mask=0。不能因为 PASS 少就当坏动作；原数据里只有 5 个此类步骤，但在线采集可能出现更多。
- F≥1 但反馈不可靠/上下文超长：保留轨迹与失败统计，loss mask=0；不能无反馈硬套教师，更不能降级为正 SFT。

完整历史一直保留。被 mask 的步骤不等于从后续动作的上下文中删除。只对当前 assistant 回答 tokens 计算损失，不训练 task/system/history/observation/反馈文本。

### 8.4 教师与损失的具体定义

学生看到 `h_s`；教师看到 `h_s + f_s`，默认采用阶段 A 通过验证的 C2，不附完整原回答。教师与学生的底座相同，教师 LoRA 参数使用学生的移动平均；初始化必须**完整复制初始学生 adapter**。冻结教师梯度，不能让教师在同一梯度图里被更新。

对原学生回答的第 j 个 token：

```text
p_sj = πθ(· | h_s, a_s,<j)
q_sj = stopgrad[πθT(· | h_s, f_s, a_s,<j)]

L_SFT = mean_{s∈G} [ mean_{j∈response_s} −log p_sj(a_s,j) ]
L_SD  = mean_{s∈B} [ mean_{j∈response_s} KL(p_sj || q_sj) ]
L     = L_SFT + λ L_SD,    λ = 1.0 作为初始候选
```

这里的蒸馏不是“给失败回答一个负的 CE”，也不是把 Codex 反馈当成要生成的标签。它在同一原回答 token 前缀处，使不见反馈的学生分布接近看过反馈的教师分布。教师仍会看到已经 teacher-force 的原回答前缀 `a_<j`；“不附原回答”指不在教师 prompt 再完整放入一次，不意味着教师能不条件于前缀。

初始实现用**学生 top-100 词表项 + 一个 tail 概率桶**近似 reverse KL：每个位置选学生 top-100 token IDs，分别收集 p、q 在相同 ID 上的概率，剩余概率合并为 tail，再计算 KL。不能分别选两套 top-k，也不能只对 top-k 重归一化而丢掉 tail。它是分桶近似，不是完整词表精确 KL；记录覆盖质量，若明显不足再考虑 K=256 的实现消融。

两个分支各自先按回答 token 平均，再按步骤平均。否则本批 FAIL 步骤多、回答更长，会自然淹没 SFT。实现梯度累积时，每个 G 步的损失乘 `1/|G|`，每个 B 步乘 `λ/|B|`，而不是统一除以全部步骤数；两个分支为空时对应损失为 0。

若整批都无可训练步骤，跳过 optimizer 和 EMA 更新，保留“更新机会”计数，报告真实 optimizer 次数；不能造样本凑满，也不能调用有 weight decay 的空更新掩盖差异。在线 SFT 对照可能出现无 G 批，因此“每轮 18 次”严格指更新机会。

先采用同步、每批一次更新：生成策略就是该批更新前的学生，反向传播期间不改变参数，因此不需要先引入 PPO ratio/clipping 或经验回放。以后若复用一批多轮、异步产生陈旧 rollout，就必须重新设计 off-policy 修正，不能沿用此简化假设。

### 8.5 起步超参与诊断

| 参数 | 阶段 B 初始建议 | 理由/限制 |
|---|---|---|
| LoRA | r=8，alpha=16，dropout=0；q/k/v/o/gate/up/down 七类投影 | 与原 SFT 结构一致 |
| 优化器 | AdamW，weight_decay=0，沿用原 betas/eps 并记录 | 不同时更换大量设置 |
| 学习率 | 5e-5；前 5 次非空更新线性 warmup，随后恒定 | 比原 SFT 的 2e-4 保守；是待检验建议，不是论文最优值 |
| 梯度裁剪 | 全局 norm=1.0 | 记录裁剪前 norm 与触发比例 |
| λ | 1.0 | 仅在分支各自归一化后有此含义；监控两分支梯度量级 |
| 教师 EMA | `θT ← 0.95 θT + 0.05 θstudent_after_update` | 一个采集批内教师固定；这是 LoRA 参数 EMA，不宣称等价于完整权重 EMA |
| 精度与内存 | bf16、microbatch=1 个步骤、token 分块计算 LM head/KL | teacher forward 无梯度；共享底座时独立学生/教师 adapter；实际显存待测 |
| 上下文 | 学生保留原历史；教师训练上限候选 40,960，先校验模型/内核支持 | 教师超限仅 mask 该 B 步；不暗中截历史；统计覆盖 |

λ=1 并不保证两个分支影响相同。调试前 3 个更新记录分支 loss、梯度 norm/方向相容性、top-k 质量、输出长度/熵、每维 FAIL、有效反馈率和跳过率。先定位信号质量与数值问题；若明显失衡，再用新的 pilot 配置比较 λ∈{0.3,1.0} 或 lr∈{2e-5,5e-5}，不要在同一次正式运行中随结果任意改权重。

必要实现检查：C0/教师 response token 对齐；teacher stop-gradient；初始化教师与学生等价；没有反馈时相同 teacher/student 的 KL 接近数值零；在小词表例子上验证 top-k+tail；梯度累积与一次完整小批计算一致；选中 step 数与 loss 掩码一致。这里需要少量数值单测，因为错误会直接改变优化目标。

阶段 B 以预定最终 checkpoint 做一次沿用现有协议的 dev57 评估，两个分支同预算同初始种子。它用于筛查退化和程序正确性，不用 36 次更新、1 个 seed 就宣布算法优胜；不反复在 dev57 上选择最幸运 checkpoint。原 dev57 已参与过研究选择，后续不能把它描述为全新未见的最终测试集。

## 9. 阶段 C：验证完整训练收益与机制

通过阶段 B 的数值、采集、反馈与行为检查后，冻结 prompt、λ、学习率、EMA、掩码、运行预算及评估协议。主要比较两个分支：

| 分支 | 在线样本 | 损失 | 检验 |
|---|---|---|---|
| C-SFT | 当前学生 train90 rollout | ZeroFail3 SFT | 相同在线采集条件下的必要基线 |
| C-MIX | 当前学生 train90 rollout | 同一定义 SFT + FAIL-SDPO | FAIL 反馈是否带来额外收益 |

每个分支 3 个种子（101/202/303），每 seed 5 轮 train90：450 条训练轨迹、90 个更新机会；主要对比总计 2,700 条训练轨迹。分支之间匹配初始权重、题目顺序、采集条数、更新机会及环境预算；策略分化后轨迹本来就会不同，不能声称逐条训练数据仍相同。额外报告实际 optimizer 次数、训练 tokens、反馈调用与时间/显存成本，不把“同轨迹数”叫作“同算力”。

主结果为预定最终 checkpoint 的 AppWorld dev57 官方任务指标（沿用现有 TGC/SGC 定义、任务集及推理协议），报告各 seed、均值与波动，辅以按任务家族配对分析；3 个 seed 不支持很强的普遍性结论。可在固定轮次留 checkpoint 做趋势图，但主比较不改为事后最佳 checkpoint。若需要独立最终检验，应另设此前未用于调整方案的任务集；本计划不假定已经拥有该数据。

机制指标：R1–R8 FAIL/step 与每任务发生率、有效进展、重复无效操作、提前完成、平均步数、反馈覆盖、G/B 比例、mask 原因与总成本。仅 FAIL 下降、任务完成率下降，不能判为成功。

在主要两分支比较完成后，最有价值的额外消融是 **FAIL-SDPO only**，用于判断 SFT 稳定项是否必要；资源允许时再加入 `SFT + 仅标签-SDPO`，区分具体诊断与通用规则提醒。C3 完整原回答只有阶段 A 确实支持时再列入训练消融，默认不扩成大网格。

若混合方法优于在线 SFT，却不能优于现有离线 ZeroFail3，也应如实报告：前者回答 FAIL 信号的增量价值，后者回答当前最实用的训练方案是否被超越，两者不是同一个比较。

## 11. 方法依据与迁移边界

- [Reinforcement Learning via Self-Distillation / SDPO](https://arxiv.org/abs/2601.20802)：支持用反馈条件教师提供 token 级蒸馏信号；[官方实现](https://github.com/lasgroup/SDPO)可核对 teacher reprompt、EMA 与蒸馏目标。本计划的 step-level rubric 路由、5 题批次、LoRA 超参和阶段 A 门槛属于针对当前实验的设计，不是论文已证明的设置。
- 官方 SDPO 代码研究快照：commit `7c457fc1b1f636ae794eb0362ba37d4743b06fbc`，重点为 `verl/trainer/ppo/core_algos.py` 的 self-distillation loss、`verl/trainer/ppo/ray_trainer.py` 的教师输入构造及 `experiments/rich_feedback/run_sdpo.sh`。实现前再次核对所选版本，不能把论文中的全参数学习率原样迁移到当前 LoRA。
- [TRL experimental SDPO](https://github.com/huggingface/trl/tree/dc96165438c379fed318ca5ab15a2d1c76325962/trl/experimental/sdpo)：可参考 `loss_utils.py` 的分桶 KL 和教师管理；必须自行验证 adapter 初始化及上下文长度，不直接继承短 prompt 默认值。
- [AppWorld 相关 on-policy distillation 文章](https://arxiv.org/html/2610.15840v1)：用于参考 agent 任务中的状态分布与局部动作优化问题；外部强教师/价值加权设置不能直接证明这里同模型加 rubric 反馈的教师有效，阶段 A 正是验证这个缺口。

本计划将“反馈能否帮助重新决策”“教师在原 token 前缀上是否提供合适梯度”“在线混合训练是否提升最终任务表现”分别放在 A、B、C 验证，避免用第一项替代后两项。
