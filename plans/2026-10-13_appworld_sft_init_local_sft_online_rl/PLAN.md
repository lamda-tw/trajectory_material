## 3. 已完成：按确定的评分规则构建局部 SFT 数据

### 3.1 唯一入选条件

对全量 9,886 步计算：

S_step = sum(score(R_i), i=1..8) = #P − #F。

P=+1，F=−1，U=0，N=0；八个维度等权。**所有且仅有 S_step≥4 的步骤入选。** 不采用 P/(P+F)，不为凑满 30% 增补 3 分步骤。

| 阈值 | 步骤数 | 占全量 | 含至少一个 F |
| --- | ---: | ---: | ---: |
| ≥3 | 4,659 | 47.13% | 507 |
| **≥4：本轮采用** | **2,623** | **26.53%** | **106** |
| ≥5 | 863 | 8.73% | 13 |

精确前 30% 为 2,966 步，需从 2,036 个同为 3 分的步骤中选 343 个。采用 ≥4 保持同分同待遇，且比例接近原目标。该阈值根据本批标签分布确定，不依据本轮训练后的 DEV 成绩调整。

正式筛选清单覆盖 88 个任务、431 条轨迹；其中 41 步含 U，106 步含 F。R1=F 有 6 步，R4=F 有 34 步，R5=F 有 1 步（各集合可重叠）。这些步骤满足总分就保留，不再否决。净分是筛选启发式，不是正确率或已验证的学习价值；普通正向 SFT 会模仿入选目标的全部 token，F 的扣分不会变成负向 loss。

## 4. 第三步：把三个“轮数”分别确定

“每批 RL epoch=1”不表示整个实验只训练一轮。必须分别配置和记录：

| 名称 | 含义 | 本次建议 |
| --- | --- | --- |
| 在线采样轮数 | 当前模型遍历 train90、采样并更新的次数 | 5 个采集/更新轮；轮内行为模型固定，下一轮用上轮最终模型；第 1 轮复用现有池 |
| 局部 SFT epoch | 固定局部监督数据被完整学习的次数 | 拟定 5 遍；总监督量为 5×T_SFT |
| 每池 RL 遍历次数 | 同一批已经采样的 RL 数据被重复优化几遍 | 初始建议 1 遍，工程检查后冻结 |

### 4.1 为什么不把所有 epoch 都直接设为 5

SFT 是对固定监督目标重复学习。本次先固定 5 遍作为候选预算，保留第 1/3/5 轮评测观察学习过程；这不是对 5 遍最优或足够收敛的预先判断。

每轮先准备完整 540 条池，池内分批更新参数，全部用完才重新采集。每池遍历一次可以包含多次 optimizer.step；它不是每轮只更新一次，也不是每批重采样。

如果同一批 RL 数据重复更新 5 遍，第二遍之后模型已经偏离采样时的行为策略。多遍更新可以提高样本利用率，但需要核对概率比、KL、clip fraction 和更新幅度；不能因为原来的 SFT 用过 5 个 epoch，就自动把每批 RL 也设为 5。

因此，当前建议是“5 轮在线采样 + 5 遍局部 SFT”，每批 RL 先按 1 遍设计。是否需要增加每批 RL 的更新遍数，应根据工程试跑与训练信号判断，不预设 1 遍一定充分，也不预设更多遍一定更好。

### 4.2 不再预填与本次数据无关的预算

筛选规则与 N 已确定；其余正式配置在数据构建和工程测量后补齐：

| 参数 | 确定依据 |
| --- | --- |
| N、T_SFT | 已实测 N=2,623，T_SFT=205,238；五遍 1,026,190 token |
| 每题新采样数 G | 候选 6；工程试跑核实成本后冻结，不根据 DEV 改动 |
| 每批题目数 B | 候选 6；核实轨迹长度、显存和梯度累积成本 |
| 每池 RL 遍历次数 K | 初始建议 1，结合策略偏移检查冻结 |
| 学习率、KL 系数、SFT 混合系数 | 本模型联合训练的数值与梯度检查 |
| attention、微批大小和并发 | 仅物理 GPU1；单进程/单卡，实测显存后冻结 |
| 随机种子与任务顺序 | 本实验独立记录，保证可复现 |

若在线轮数为 E=5，每轮每题采样 G 条，则正式 RL 消费量为 E×90×G；首轮复用现有池，新增正式采集量为 (E−1)×90×G。若每批 B 题、每次完整批次遍历后更新一次、每批重复 K 遍，则更新数为 E×ceil(90/B)×K；尾批按实际题数归一化。具体执行器若采用其他优化粒度，须按实现重新计算并记录，不能套用该式。

候选 B=6、G=6、K=1 时：每轮 15 批，5 轮共 75 次联合更新、2,700 条 RL 消费轨迹（旧 540、新采 2,160）。5 遍 SFT 对应 13,115 次完整原始目标消费。学习率 5e-6、beta=0.01、lambda=0.1 等工程候选及理由详见 draft JSON；这些是供审查和工程验证的起始值，不声称已测定最优。

局部 SFT 总监督量拟为 5×T_SFT。根据最终更新数编排消费计划，使五遍目标 token 完整覆盖；微批或 loss span 拆分只用于计算，不丢弃原始响应内容，不制造新动作；如使用 span 拆分，每段必须保留正确因果前缀，目标 token 不重计、不漏计。每个样本每遍恰好消费一次，不因提前耗尽或尾批而额外循环或丢弃。

**本步产物：** 写清全部实际数值的 training_config.json、预算表和 SFT 消费计划。正式训练开始前必须具体化；不能带着未填配置启动。

### 4.3 学习率跨轮连续衰减，不重新 warmup

候选学习率以全局联合 optimizer 更新编号计数：第 1—4 次从 1.25e-6 warmup 至 5e-6，之后连续余弦衰减，第 75 次到 5e-7。每轮结束不重置学习率、optimizer 或 scheduler；若总更新数改变，正式训练前重算调度并冻结。scheduler 的实际步号须通过测试与此约定一致。

RL 与 SFT 共享同一个 optimizer 的学习率。lambda 调节 SFT 梯度相对强度，当前工程候选为 0.1；本次不另设逐轮 SFT 学习率，也不把步骤分数作为 CE 权重。新联合运行从已有 LoRA 权重创建新 optimizer 状态，后续各轮连续保留状态。

历史五轮固定 2e-4 的结果出现退化，不能证明本次同样会退化或单靠衰减便能解决。五遍不是最优性结论；保留第 1/3/5 轮同协议评测，最终以预定第 5 轮比较，避免事后挑结果。数值候选仍需单卡工程检查，尚未启动训练。

## 7. 第六步：执行多轮局部 SFT + 在线结果 RL

### 7.1 每轮整池采集，池内逐批联合更新

本轮采用 PPO/GRPO 风格的固定行为策略轨迹池。初始模型 A0 是已有 train90 SFT LoRA；基座冻结，只续训该 LoRA 副本。reference 全程为 A0；old policy 则每个采集轮更换一次。

每轮执行：

1. 第 1 轮导入已经核实的完整 540 条 A0 轨迹；后续轮使用上一轮最终模型，在 train90 每题采集 6 条。采集期间参数固定，记录原始 token、old log-prob、官方奖励和行为模型哈希。
2. 540 条全部准备好后停止推理服务，使用 GPU1 计算/缓存 A0 reference 概率，再进入该池的训练阶段。轮内不启动新轨迹采集。
3. 固定每题 6 条的组内优势，随机排列任务组。候选每批 6 题，即每池 15 批；此数字仍待完整池试跑决定。
4. 每批在当前训练参数上计算该批 RL/KL，以及固定 SFT 步骤子集的 CE。SFT 数据每轮随机排列并完整学习一次；候选 13 批×175 步、2 批×174 步。不要求 SFT 与 RL 子集来自相同任务。
5. 通过单样本微批积累梯度，正确归约后统一裁剪，执行一次 optimizer.step。学习率按已提交全局更新编号计算一次。参数在每批结束时改变；old log-prob 和 reference 缓存均不改变。
6. 保存完整恢复 checkpoint 和消费游标，直接处理池中的下一批。后面的批次允许相对采集策略出现偏离，以原始行为概率计算 clipped ratio；不能重写 old log-prob 或强制 ratio=1。
7. 全池用完，保存该轮最终模型；按既定轮次评测后，再以此模型采集下一轮 540 条。

~~~text
A0 + 旧池540 → [联合更新1 → … → 联合更新15] → A1
A1 采集540  → [联合更新16 → … → 联合更新30] → A2
……
A4 采集540  → [联合更新61 → … → 联合更新75] → A5
~~~

图中的 15/75 为工程候选。整池采集减少推理/训练切换，但不自动保证池内多次更新稳定。SFT 梯度也会造成策略偏离，PPO clipping 不约束整个联合梯度，因此完整池试跑必须检查后期批次的 ratio、KL 和梯度。最终批次数由 agent 根据 GPU1 实测决定，不按 DEV 成绩调参。

训练目标：

L_total = L_GRPO + beta × L_KL + lambda × L_local_SFT。

L_GRPO 使用本批行为策略概率的 clipped ratio 目标；KL 的具体估计器、归约方式、beta、lambda 与学习率必须在工程检查后写入配置。RL/KL 采用执行手册中的轨迹归约；局部 SFT 则明确固定为步骤等权：L_local_SFT = (1/M) × sum_s [(1/T_s) × sum_t CE(s,t)]。M 是本次更新的实际原始步骤数，T_s 是该步骤完整目标 token 数，含原始 EOS，不含历史/padding。分段或微批梯度贡献为 CE_sum/(M*T_s)，不能把分段视为新步骤，也不能简单等权平均大小不同的微批均值。实现与基础数值验收已在步骤 4 完成；完整池稳定性与正式数值容差在步骤 6 冻结。

终态奖励的组内优势为：

A_i = (R_i − mean(R)) / (std(R) + epsilon)。

标准差约定与 epsilon 写入配置；全等组优势置零时仍计算预定 SFT 与适用的 KL。prompt 与工具观察没有 RL loss，SFT 历史不监督。步骤总分仅决定离线样本入选，不作为新 rollout 的 RL reward，不作为 CE 权重，也不变成负向 token loss。

默认每池 RL 遍历次数 K=1。若工程检查后改为 K>1，必须在正式训练前修订并冻结：每次 optimizer.step 都是当时参数上的联合更新；old log-prob 始终对应最初采样策略；相应重新编排 SFT 消费，使总量仍为 5×T_SFT，不能每重复一遍 RL 就无记录地额外重复 SFT。正式运行后不按 DEV 表现切换 K。

没有步骤级 RL 奖励时，不把轨迹优势说成已精确定位到错误动作。本实验回答联合流程及最终效果；没有纯 RL 对照时不能单独归因局部 SFT 的贡献。

## 2026-10-14：更新次数与步骤等权规则

“一次联合更新”指每个批次将 RL、KL、局部 SFT 梯度合并后执行一次 optimizer.step，并非一整轮只更新一次。当前 B=6、G=6、K=1 候选下，90 题每轮分成 15 批，五轮共 75 次更新。每轮固定 2,623 个 SFT 步骤各学习一次，分到这 15 次更新中，每次约 175 步；微批 forward/backward 次数不等于参数更新次数。

对比 2026-10-13_appworld_rubric_local_sft_epoch5_ddp：当时是纯 SFT，2,440 步、每次 2 步，所以每轮 1,220 次，五轮 6,100 次更新。当前继续训练已有 90 条轨迹 SFT 的同一 LoRA 副本，基座冻结；不是全量微调或新增并联 LoRA。更新次数减少源于候选有效批量和联合采样编排，而不是 LoRA 算法的要求；相同五遍数据不代表相同优化过程，75 次不能据此认定足够或更优。学习率仍按全局更新步号连续衰减，不在轮次边界重置。

局部 SFT 必须采用 `mean_steps(mean_target_tokens(CE))`，使同一次更新中每个原始步骤等权。旧五轮纯 SFT 也采用此归约；原联合计划的全局 token 平均已由本规则替代。监督 token 预算仅用于核算。该修改不改变已验收的筛选、样本、编码或 mask；不把数据验收误报为 trainer 已实现。RL/KL 的轨迹奖励与归约仍按执行手册单独定义。
