# AppWorld Rubrics 选样效果与模型行为研究计划

日期：2026-10-15（北京时间）。状态：计划已整理，等待当前 SFT+RL 单池任务完成；本次不启动采集、评分、训练、评测或自动接力程序。

研究目标是判断：在固定训练配方和步骤预算下，纯 rubric 评分选样能否优于随机选样；哪些数据和行为变化与性能提升、退化有关。先研究原始 Qwen3-8B，再研究原有 SFT LoRA 初始化模型。所有 GPU 工作仅使用物理 GPU1。

## 1 已有证据与待验证问题

旧配方的 rubric/uniform 成功数为 4/57 与 6/57；后续相同新配方第一轮为 13/57 与 5/57。后一对照匹配了初始化、2,440 个步骤、1,220 次更新和任务配对，但 token、上下文、部分响应 mask 不完全一致，且只有一次重复。两组都使用相同公共质量门槛。因此它支持“共同过滤后的候选池中，当前配方下 rubric 选样有收益”，尚不能证明纯评分选样的独立效果。

同一 rubric 数据连续训练第 1、3、5 轮为 13、10、8 个成功任务，而训练 loss 持续下降。下一轮同时研究选择效果和训练强度，不预设高分步骤必然有益，也不预设取消门槛会提高成绩。

主要假设：纯评分选样可能提高有效步骤的比例，也可能偏向某些动作类型、轨迹阶段或易学行为；持续模仿这种分布可能改善局部执行但损害任务级探索、核验或终止。该假设需要数据分布、独立诊断和干预共同检验。

决策规则：

- 只有评分 prompt 或 judge 协议变更：保留合格原始轨迹，重新评分，不因此自动重采。

## 4 原始模型上的主要对照

初始化为 `/root/autodl-tmp/models/Qwen3-8B`，各组建立相同初始化的新 LoRA；另评测不训练的基线。第一优先级为 A/B 两组：

| 组 | 候选步骤 | 选择方法 |
| --- | --- | --- |
| A Random | 完整可构建训练样本的原始池 | 按题均匀无放回抽取，与 B 每题数量一致 |
| B Rubric only | 与 A 相同 | 唯一质量入选条件为 P−F≥4 |

分数是 8 个维度中 P 个数减 F 个数；U/N 计 0，保留分项标签并分析适用性差异。主实验不追加语法正确、执行成功、单代码块、最终任务成功、内容去重或排除提交步骤等质量规则。随机组不得刻意排除高分步骤。

两组共同的最低工程要求仅限来源可验证、能重建原始历史与目标、能编码训练。生成被截断本身不作为质量拒绝条件：保留实际生成内容，不能伪造 EOS。缺失历史或超出可支持长度时优先修复数据/采用可支持实现；确需排除则独立记录原因、数量、分数分布，对两组在选样前一致应用，并将结论限定于该可训练池。

B 的每题入选数定义 A 的配额；B 为零的任务，A 同样为零，报告覆盖损失。每轮各目标出现一次，监督完整原始响应，不为了凑 token 切断动作。固定同题配额意味着主结论是“在 B 所定义任务分配下的步骤选择效果”，不声称已检验最优任务配额。独立记录监督 token、输入 token、动作长度与训练时间。

主实验保留 P−F≥4 阈值，不在看到 DEV 后改成 top-K、归一化分数或别的阈值；这些属于后续独立消融。

## 5 训练与评测协议

建议冻结以下起始配方，以衔接已有 13/57 对照：LoRA r8/alpha16/dropout0，q/k/v/o/gate/up/down；AdamW 固定 LR=2e-4、weight_decay=0、无梯度裁剪；bf16、梯度检查点。单卡每个 microbatch 一个步骤，累积两个步骤后更新；每步目标 token 内平均 CE，再对步骤平均，保持全局两步的目标。末尾不足两步时按实际步数归一化，不能丢样或复制补齐。

先做独立 smoke，验证完整响应 mask、两步累积的 loss/梯度、保存重载和最长样本；smoke 权重不进入正式实验。若内存要求调整实现，先通过数学等价检查；若必须改变配方，统一更改 A/B 并在评测前重新冻结，记录原因。

每组计划 3 次重复，训练 seed 为 20261015、20261016、20261017；Random 的抽样 seed 同值但使用独立随机数流。每对 A/B 使用相同初始化 seed、任务顺序及更新内任务配对。B 的阈值集合固定，A 重新抽样，明确报告两种不确定性来源；不把共享基线计作独立重复。

每次训练 5 轮，保存并评测第 1、3、5 轮；第 1 轮 A/B 差值为预先指定的主要终点，其余用于训练强度分析。不得按第 1 轮胜负取消剩余组或重复。数值异常或资源故障暂停并留证，不能把失败运行隐藏为未发生。

评测固定相同 agent prompt/runtime：thinking 关闭，temperature=0、seed=100，50 步、32,000 上下文、每步生成上限 3,000 token，官方任务终态测试；正式冻结前核对与实际脚本一致。DEV57 已用于历史探索，结果定位为开发证据。开始前盘点未参与调参、训练且按任务家族隔离的保留评测集；若可用，冻结并在方案确定后只作最终验证。不存在独立保留集时明确报告该限制，不把 DEV57 重命名为独立测试。

指标包括官方成功率、逐题得失、家族覆盖，以及步骤/上下文上限、无代码终止、重复动作、执行错误和提交后官方失败。报告各 seed 和均值，以任务家族为单位做配对 bootstrap；不同 seed 的同题结果不能当作独立题目。主实验共 6 次训练、18 个检查点评测，加基线；先实测单卡吞吐再估算时间，不使用旧双卡耗时直接承诺完成日期。

## 6 门槛和机制消融

A/B 完成后，补 C（旧质量门槛加随机）与 D（旧质量门槛加 rubric）。旧门槛完整快照，包括执行、语法、去重、排除提交等，不能只恢复其中一部分却称为相同旧管线。四组使用同一最新评分、完整响应监督及相同训练配方。

严格四组比较需从各池容量计算共同每题配额，在看到这批结果前冻结。D 先以 P−F≥4 入选；统一配额可取各题 B/D 入选数及 A/C 容量的最小值，再固定 seed 下采样。四组全部按这套共同配额重新构建；若预算与主 A/B 不同，重新训练对应 A/B，不能直接拼接旧结果。该消融回答共同支持范围内门槛与评分的关系，并报告被移出的任务和步骤。

机制分析按以下顺序推进：

1. 数据层：比较动作类型、轨迹位置、长度、重复率、分项标签、适用维度数，以及探索/执行/验证/终止覆盖。动作类型标注仅用于分析，不回流主实验筛选。
2. 学习层：在不参与训练、事先固定的步骤诊断集上，对比不同分数和动作类型的 CE/概率变化；不拿各组自身训练 loss 排名数据质量。
3. 行为层：对全部成功转失败和失败转成功任务定位首个关键分歧，采用统一错误分类，纳入同样失败及同样成功的对照，保留无法判定案例。
4. 干预层：根据开发证据选择一个明确机制做后续实验，例如固定预算补齐验证/终止动作，或匹配动作类型与长度后比较评分排序；预先写清预测和反证。观察相关性不直接宣称某个 rubric 维度导致收益。

阶段性报告必须解释“rubric 是否有效”和“为何可能有效”所用证据的不同强度。数据分布改变可能正是选择策略的作用路径，不要求主实验把所有分布强行匹配；匹配分析作为机制消融单列。

## 8 执行顺序与交付

1. 验收前置 SFT+RL 任务完成及 GPU1 释放。
2. 核实启动时最新 prompt，完成轨迹/标签复用验收，必要时重评或重采。
3. 冻结模型、prompt/schema/judge、原始池、训练样本、选样规则、seed、配方与评测协议的文件及哈希。
4. 单卡 smoke 通过后运行原始 Qwen 基线及 A/B 三次重复，串行训练与评测。
5. 汇总数据、检查点、逐题行为和统计，开展门槛/机制消融。
6. 运行 A0 同池实验，再运行 A0 自生成数据实验，分别汇报。

后续独立实验目录必须包含：数据来源与复用决定、逐步入选/未入选原因、完整目标 mask 验收、资源绑定证据、冻结配置、训练曲线、checkpoint 哈希、逐题评测及轨迹、跨 seed 汇总、行为机制分析、耗时与故障记录。未完成项目显式标注，不以训练 loss 下降代替任务效果。
